# dev.11 — импорт готовых Excel-отчётов по двум образцам

## Причина

Прежний импорт требовал лист `_Системная карта`, который есть только в выгрузках
программы. Готовые рабочие книги его не содержат.

## Поддерживаемые источники и проверка

| Источник, приложенный пользователем | Тип сетки | Заполненные ячейки | Формулы |
|---|---|---:|---:|
| пример дочерних обществ.xlsx | четыре недели каждого месяца | 1973 | 354 |
| пример отчёта головной плоащдки.XLSX | месячные пары План/Факт | 330 | 210 |

Числа получены чтением непустых ячеек и подсчётом ячеек `data_type=f` исходных книг.
Оба оригинальных файла прошли локально: импорт через bridge без системной карты,
отсутствие отчёта в рабочем списке до подтверждения, подтверждение, редактирование
L9, перезапуск, экспорт, сравнение всех исходных формул и объединений, повторный импорт.
Исходные пользовательские файлы и их содержимое в Git не включены.

В головном образце A1 содержит 2026, месячные колонки — 2025. Программа показывает
предупреждение и сохраняет даты источника. Автоматической замены года нет.

## Поведение

Та же кнопка «Импорт Excel» сначала проверяет штатную системную карту. Если карты нет,
применяет отдельный адаптер двух исходных форм. Повреждённая существующая карта не
обходится этим адаптером. Неизвестные структуры, лишние данные за границами образца,
скрытые листы и неподдерживаемые формулы блокируют импорт с сообщением.

Предпросмотр показывает листы, названия, исходную сетку и результаты формул.
Подтверждение публикует книгу в списке «Сохранённые отчёты Excel» выбранной организации.
Готовая книга — отдельный матричный отчёт, а не произвольное разнесение месячных сумм
по дням. Дневные рабочие формы и их значения не заменяются.

Исходные значения начиная с строки 9 можно менять двойным щелчком или Enter.
Расчётные ячейки, даты и заголовки не изменяются. Сохранение пересчитывает формулы backend,
проверяет ревизию и добавляет неизменяемую запись истории. Пустота и ноль различаются.
Переход между отчётами блокируется при несохранённых правках; есть отмена правок.
Экспорт берёт исходную книгу и применяет сохранённые изменения, сохраняя формулы,
форматирование и объединения. Повторный исходный файл определяется SHA-256 в области
организации. Изменённый файл с другим SHA-256 импортируется как отдельная книга.

## Архитектурная граница

Миграция 0009 добавляет хранилище исходных книг и неизменяемую историю правок в той же
SQLite. Адреса Excel используются только как координаты внутри конкретного исходного
документа, не как идентификаторы производственных операций. Оригинал неизменяем.
Резервная копия создаётся перед подтверждением и сохранением. До подтверждения книга
хранится только как staging и не появляется в рабочем списке.

Адаптер вычисляет используемые в образцах арифметику, ссылки, диапазоны, SUM,
CONCATENATE и CHAR через ограниченный AST; Python eval, макросы и внешние вызовы не
используются. Это не универсальный движок всех функций Excel. Выгруженную книгу
Excel пересчитывает штатно при открытии.

## Границы

- Проверены именно два приложенных образца. Исходный ежедневный отчёт без системной
  карты этим адаптером не поддерживается.
- Автоматического сведения исходной книги с дневными формами нет.
- PDF и подтверждение руководителя относятся к дневным рабочим формам; для исходных
  книг здесь реализованы импорт, редактирование значений, пересчёт, история и Excel-экспорт.
- Изображений в двух приложенных книгах не найдено; изменение изображений не проверялось.
- Windows-сборка сохраняет встроенный Fixed WebView2. В проверку настоящего окна добавлено
  открытие синтетического импортированного отчёта и проверка результата формулы 675.
