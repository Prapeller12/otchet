Область: шесть замечаний ручного тестирования от 06.09.2026.

## Проверки до публикации

- Backend: `python -m pytest -q` — 225 тестов.
- Frontend: `vitest run --config vite.config.ts` — 19 DOM-тестов.
- Ruff format/check, mypy backend/scripts, TypeScript обоих проектов.
- Production Vite build, проверка автономности frontend и JSON/TypeScript-контрактов.
- Self-test приложения использует временную БД и синтетические данные.

## Результаты сценариев

1. Получено 20 / Использовано 3 на 14 сентября при пустых предыдущих днях:
   предустановленный остаток 17 до сохранения и после него. Предпросмотр не создаёт
   фактов. Расход 2 в октябре уменьшает остаток до 15.
2. Заголовки изменяются перетаскиванием границы и стрелками клавиатуры. Ширины
   сохраняются в SQLite; закреплённые столбцы используют новые смещения.
3. Месяцы раскрываются независимо. Скрытие и повторное раскрытие сохраняют черновики.
   Календарь содержит 365/366 дней, включая 29 февраля високосного года.
4. Техническая строка, бейдж и демонстрационный подзаголовок убраны.
5. Название редактируется рядом с заголовком и сохраняется отдельно для отчёта
   и организации. Неправильные названия/ширины отклоняются backend.
6. Готовые пресеты воспроизводят комплектность, прямой ввод наличия из образца,
   накопительный факт и договорное отклонение. Коды/формулы скрыты в расширенной настройке.
   Сохранены контрольные результаты 23 и 30 для 12 позиций исходной книги.
7. Годовой export → preview → commit проверен для всех трёх форм, включая дробное
   значение в начале года и подтверждённый ноль в конце. Прежние проверки импорта,
   организаций, изображений, резервных копий и неизменяемых фактов проходят.
8. Обновление БД с 0006 на 0007 и повторный запуск проверены: дата прежнего
   начального остатка сохраняет месячный смысл, прежний стандартный пресет исправляется.

## Соответствие источникам и границы

Координаты формул исходников и правила переноса описаны в
[ADR-0004](../decisions/0004-calendar-and-default-calculations.md).
Исходные пользовательские книги в Git не добавлялись и не изменялись.

Интерфейс работает с текущим календарным годом. Начальный остаток задан на дату,
перенос между годами не автоматизирован. У старой настройки без даты миграция
использует начало месяца обновления: при отложенном обновлении дату нужно проверить.
Свёрнутые месяцы остаются частью расчёта и годовой книги. Пустые первичные значения
отличаются от нулей; BALANCE суммирует только внесённые движения.

Импорт принимает собственные экспортированные книги; произвольные адреса A1,
межлистовые ссылки и полный язык Excel не поддерживаются. Итоги в выгрузке — снимки
с формулами в примечаниях. Пользовательские бизнес-привязки не угадывались.

Локальная проверка интерфейса выполнена в DOM, без настоящего окна WebView2.
Windows workflow собирает приложение и запускает self-test упакованного EXE
(включая 17, 23/30, високосный календарь, название, изображения и Excel-обмен).
Self-test не подтверждает открытие окна и native file dialogs; они требуют ручной
проверки. Тестовый ZIP использует системный WebView2. Результат конкретной
Windows-сборки проверяется в GitHub Actions после публикации.

Ручной сценарий находится в `TESTING.txt` внутри ZIP. Для обновления используйте
копию `data/reporting.sqlite3` из закрытой программы, сохранив прежнюю папку целиком.
