# Ручная проверка dev.13

Распакуйте Windows ZIP в отдельную папку, запустите start.cmd. Перед переносом существующей data/reporting.db сохраните копию всей предыдущей папки.

1. Дочерние общества → нужная организация → Настроить рабочее поле. Одна деталь, входимость 4, два производителя. Заполните номер, обозначение, договорные объёмы. Примените настройки.
2. Сентябрь 2026, план C6 = 1000. Сохранить план. Начальный остаток 500, поступления А 2000 и Б 1000. Расход А 100 в неделю 01–06, Б 200 в 07–13, А 50 в 28–30. Сохранить.
3. Остаток на 07–13 = 3200; на 28–30 = 3150. Дефицит = −500 в обоих случаях. Пять недель сентября видны. Октябрьские поля пока пусты.
4. Перезапустите программу. Данные, настройки, план должны сохраниться.
5. Уберите лишнего производителя без данных. Деталь и второй производитель остаются. Производитель с данными архивируется и остаётся доступен в истории соответствующего года.
6. Экспорт Excel, изменение вводимых значений, импорт, проверка сопоставления/предпросмотра и подтверждение. Расчётные значения меняются только после пересчёта backend.
7. Печать / PDF A4: все пять недель сентября на одном листе по ширине, значения расхода по производителям, склад на выбранную неделю, красный дефицит. При большом числе строк допустимы следующие страницы.
8. Подтвердить данные. Изменение количества, плана или недели остатка требует новой проверки.

Ограничения: месячные поступления вводятся общей суммой без даты внутри месяца; формула по решению владельца прибавляет эту сумму при расчёте выбранной недели. Начальный остаток каждого месяца задаётся явно. Прежняя «Поставка» не переинтерпретируется как расход.
