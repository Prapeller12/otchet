# dev.22 — ключи пользователей и подпись отчётов

## Как пользоваться

1. Распакуйте новую сборку в отдельную папку. Для переноса данных закройте старую
   программу, сохраните резервную копию и перенесите рабочую папку `data` вместе
   с используемым `config/app.local.toml`. Если путь базы переопределён, переносите
   именно эту базу. При первом запуске программа создаёт копию перед миграцией.
2. Откройте «Ежедневный отчёт», «Головная площадка» или нужное дочернее общество.
   Сохраните изменения и выберите «Месяц печати и проверки». Для дочернего общества
   также проверьте выбранную неделю расчёта остатков.
3. Нажмите «Подтвердить данные». При первом использовании заполните ФИО,
   PIN от 6 до 128 символов и повтор PIN, затем «Создать ключ пользователя».
   Этот первый профиль становится администратором ключей.
4. Выберите подтверждающего пользователя, введите его PIN, поставьте отметку
   «Я проверил данные и подтверждаю их верность» и нажмите
   «Подтверждаю верность данных». Создание ключа само по себе отчёт не подписывает.
5. Для другого подписанта откройте «Добавить пользователя», задайте его ФИО и PIN,
   выберите администратора и введите PIN администратора. Профили и ключи общие
   для локальной базы программы; они не заменяют роли централизованного доступа.
6. Нажмите «Печать / PDF А4». Внизу каждой страницы — ровно две строки:
   автор / UTC-время / Ed25519; отпечаток ключа / полная подпись Base64.
   Закрытый ключ в отчёт не включается.

## Значение статусов

| Статус | Что делать |
|---|---|
| Данные не подтверждены | Проверить сохранённые данные и подписать |
| Подтверждено | Подпись корректна и относится к текущему снимку |
| Данные изменились | Снова проверить отчёт и подписать новую версию |
| Подпись недействительна | Не использовать прежнюю отметку; проверить базу и резервную копию |
| Прежняя отметка без криптографической подписи | Отметка dev.21 сохранена; требуется новая подпись по PIN |

Проверка подписи выполняется автоматически при загрузке статуса и при экспорте PDF.
Неверный PIN, неподтверждённая галочка, устаревший снимок и расхождения данных
блокируют подписание. PIN очищается из полей после отправки и закрытия окна.
Повторное подтверждение тем же пользователем той же версии не создаёт дубликат,
но всё равно требует корректного PIN. Новый месяц или новая версия получают
самостоятельную подпись. Проверяются сохранённые данные, включая сводные значения
и выбранную неделю; область подписи соответствует прежнему месячному снимку.

## Хранение и зависимости

Для пользователя дополнительных установок нет. Сборочная зависимость
`cryptography==50.0.1` включается в portable ZIP (cffi и OpenSSL поставляются
её пакетами/PyInstaller). Ed25519 подписывает данные; Argon2id
(64 MiB, 3 прохода, 1 lane, случайная соль 16 байт) получает ключ из PIN;
ChaCha20-Poly1305 защищает закрытый ключ со случайным nonce 12 байт.
ФИО, роль и открытый ключ связаны с зашифрованным ключом через associated data.
Ключ каждого пользователя постоянный; каждое новое подтверждение содержит UUID,
UTC-время и SHA-256 снимка. PIN в базе не хранится.

Храните PIN отдельно от базы. Используйте длинный PIN/пароль: копию локальной базы
можно атаковать перебором вне программы. Восстановления забытого PIN и смены
администратора в этой версии нет; ключи переносятся вместе с резервной копией базы.
Не передавайте рабочую базу другим лицам без необходимости.

Это внутренняя криптографическая подпись снимка данных, не КЭП и не PAdES-подпись
всего PDF. Обычный PDF-reader не показывает её как сертификат. Напечатанная строка
служит идентификатором подтверждения; проверка выполняется программой по базе.
Она не обнаруживает полную замену/откат базы вместе с профилями без независимой
доверенной копии. Самодекларированное ФИО не является проверкой паспортной личности.

## Приёмочные сценарии

- Первый профиль; второй профиль с неверным и верным PIN администратора.
- Неверный PIN подписанта: отсутствие записи; верный PIN: VERIFIED после перезапуска.
- Изменение числа, настроек или недели: STALE; переподписание новой версии.
- Старые отметки мигрируют без изменения, статус LEGACY.
- UPDATE/DELETE подтверждений и ключей запрещены; внешняя подмена подписи,
  снимка или метаданных обнаруживается как INVALID.
- PDF всех трёх форм: две строки на каждой странице, включая длинное ФИО.
- Windows packaged self-test создаёт ключ и проверяет реальную Ed25519-подпись.
- Отмена формы не подписывает отчёт, не сохраняет введённый PIN.

## Выполненные проверки исходного кода

287 backend-тестов, 36 frontend-тестов, TypeScript, mypy, ruff, контракт ячейки,
сборка frontend и проверка автономности прошли. PDF двух форм дополнительно
просмотрены после растеризации: ФИО из 120 символов и полная подпись помещаются
в две строки. Третья форма использует тот же renderer; также покрыта PDF-тестом.
Результаты Windows-сборки фиксируются в GitHub Actions для коммита выпуска.
