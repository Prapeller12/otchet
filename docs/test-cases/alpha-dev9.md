# dev.9: диагностика белого окна и встроенный WebView2

Пользователь сообщил о белом окне dev.8. Точную причину на его компьютере
по фотографии установить нельзя. Подтверждено: dev.8 выпускалась в Evergreen-режиме,
без WebView2 в ZIP, и проверялась без открытия GUI.

Изменения:
- официальный Fixed Runtime x64, CAB URL/версия/SHA-256 в scripts/webview2-runtime.json;
  при сборке проверяется SHA-256 и Authenticode Microsoft; включается весь runtime;
- JS/CSS MIME-типы заданы после инициализации Windows registry associations;
- production frontend ждёт bridge до 15 секунд, не подменяет его DemoGateway;
- статическое сообщение загрузки и видимая ошибка bootstrap;
- проверка реального окна: загрузка документа, таблицы, CSS и связи с SQLite;
- Windows CI запускает распакованный EXE из пути с пробелами и кириллицей,
  открывает три формы и сохраняет снимки; публикация допускается только после успеха.

Формы, расчёты и пользовательские данные не изменены. Тест окна пишет только в
отдельную распакованную тестовую копию; в ZIP эта база не попадает.

Windows 10 остаётся отдельным ограничением: ADR-0001 имеет статус PROPOSED,
автоматическое изменение ACL запрещено утверждённой DEV-документацией.
Включение Runtime не является подтверждением совместимости с правами каталога
на Windows 10. Launcher не меняет ACL и не запрашивает администратора.

Проверка пользователем: закрыть приложение, распаковать весь новый ZIP отдельно,
запустить start.cmd. Для теста прежних данных перенести копию data/reporting.sqlite3;
прежний config/app.local.toml с Evergreen-режимом не переносить.

Результат CI и границы проверки указываются в отчёте выпуска. GitHub Windows runner
не заменяет испытание на чистых Windows 10/11 без системного Runtime.
