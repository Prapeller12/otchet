# Проверка распознавания исходных книг, dev.33

Дата проверки: 26.09.2026. Профиль `enterprise-monthly-weekly`, версия 1.
Проверялся backend текущей ветки. Пользовательские книги не включаются в Git.
Протокол описывает распознавание и ограничения источников, а не обещает успешную
запись неоднозначных данных без решений пользователя.

| Книга | Прочитанный диапазон, строки × колонки | Позиций | Вводимых значений | Контрольных полей | Ошибок формул |
|---|---:|---:|---:|---:|---:|
| КГЭ | 174 × 33 | 8 | 201 | 28 | 0 |
| Кулакова | 232 × 99 | 62 | 5121 | 184 | 13 |
| Молот | 211 × 66 | 74 | 4067 | 381 | 0 |
| Равенство | 203 × 61 | 53 | 1574 | 422 | 0 |
| СРЗ | 351 × 68 | 70 | 1941 | 254 | 2 |

Счётчики получены непосредственно из `read_reference(...).recognition` после
локального вычисления формул. Они не являются числом созданных записей БД.
Позиции считаются по действиям `UPSERT_POSITION`; значения — по типизированному
`recognition.sources`; контрольные поля — по роли `CONTROL` в `recognition.fields`.

- КГЭ: процент C4 классифицирован как контрольный процент; в количества не входит.
  Пять кодов выпуска и их месячные план/факт в шапке выделены отдельным действием
  структуры. Изготовители одной позиции сохраняются раздельно. В колонках явно указан
  2025 год, тогда как план в заголовке относится к 2026: распознавание сохраняет
  даты колонок и предупреждает о противоречии. В проекции на 2025 год автоматически
  сопоставлены все 201 вводимое значение, ошибок сопоставления нет.
- Во всех четырёх дочерних формах имеются номера недель без точных дат. Они не
  сопоставляются с неделями приложения по номеру. Нужны подтверждённые границы
  соответствующих колонок. Решение задаётся для колонки, а не каждой позиции.
- Кулакова: 13 формул содержат внешние/межлистовые ссылки; они не вычисляются
  ограниченным локальным вычислителем. Ошибка сохраняет адрес и причину, значение
  не заменяется нулём. Кеш не объявляется проверенным при невозможности вычисления.
- СРЗ: 2 повреждённые формулы и 11 позиций без изготовителя. Ошибки структуры
  указывают строки и обозначение; изготовитель задаётся явным решением пользователя.
- Молот: 4 конфликта названий при совпадающем обозначении. Они требуют явного
  решения об идентичности; совпадение названия либо локального ID не разрешает слияние.
- Полнострочные объединённые заголовки разделов не создают фиктивных позиций.
  Скрытые строки/колонки и все листы сохраняются; неизвестные и скрытые листы требуют
  явного решения включить/исключить с причиной.

Проверки на синтетических книгах без пользовательских данных:

- 99 колонок, сдвинутая строка заголовков, объединённая позиция и два изготовителя;
- `=80+50` без кеша даёт 130; ноль остаётся нулём; прочерк/дата не становятся числом;
- пустое сопоставление даёт русское сообщение без `unsupported report_type`;
- несовместимые точные границы периода блокируют также ручное сопоставление;
- поставка не может быть записана в расход;
- начальный остаток 100 + недельная поставка 20 − расход 5 = 115;
  следующие пустые недели остаются неизвестными;
- структура и значения появляются в рабочем отчёте после подтверждения и перезапуска;
  повтор не создаёт дубликаты;
- профиль переиспользуется только из проведённого пакета той же организации,
  формы, года, версии и структуры; значения берутся из нового файла;
- явное исправление структуры не изменяет оригинальный источник и сохраняет причину.

Нативный Windows EXE, прерывание процесса ОС и чистая Windows 10/11 этим протоколом
не проверялись. Структурные и календарные решения по неоднозначным пользовательским
источникам не выдумывались и не подставлялись автоматически.

## Сверка контрольных итогов

Для каждого поля роли `CONTROL` формируется отдельный результат `MATCH`, `MISMATCH`
или `UNVERIFIED` с исходным и расчётным значением, причиной и правилом округления.
Сравнение остатка/дефицита допускается только при доказанном совпадении позиции,
точного месячного периода и после пересчёта предварительной матрицы backend.
Количества сравниваются точным `Decimal` без неутверждённого округления.

Неопределённые периоды, несопоставленные проценты и итоги с неподтверждённым составом
получают `UNVERIFIED`, а не отметку успешной сверки. Сохранение исходного контрольного
поля само по себе не подтверждает его совпадение с программой. На синтетическом
примере проверены совпадение 115, расхождение 116 против 115 и неопределённые случаи.
