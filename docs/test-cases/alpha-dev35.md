# Приёмка dev.35: размеры рабочего поля

Источник: сообщение владельца от 2026-10-11 и приложенный снимок окна.
Не изменяются канонические формы, расчёты, схема БД и генераторы PDF.
Исправление касается экранных контейнеров и доступности прокрутки.

Проверять после загрузки локального шрифта, отдельно на ежедневной, головной,
дочерней и импортированной формах. Размеры ниже — размеры нативного окна,
а не гарантированные размеры клиентской области.

| Сценарий | Критерий |
|---|---|
| 1440×900 и окно снимка владельца | Таблица и строка состояния целиком в клиентской области |
| Запуск на малом экране | Нативное окно не больше рабочей области, панель задач не закрывает его низ |
| 1366×768, 1280×720, 1024×640 | Нет прокрутки документа, таблице остаётся рабочая высота |
| Широкая таблица, последний период | Горизонтальная прокрутка локальна, последний столбец достижим |
| Все строки, последняя позиция | Вертикальная прокрутка локальна, строка состояния не перекрывает ячейки |
| Развёрнутые дополнительные панели | Панели прокручиваются отдельно, таблица остаётся доступна |
| Закрепления | Верхние даты закреплены; доступный префикс идентификаторов не закрывает числовые ячейки |
| Сохранённая ширина позиции 600 px | Числа основной и вспомогательной таблиц доступны, ширина не сброшена |
| 683×384 и 667×310 клиентской области | Последние числовые ячейки достижимы и не закрыты заголовками |
| Подтверждение, PDF, переход с черновиком | Диалоги внутри окна, нижние действия достижимы |
| Настройки поля и создание пяти заготовок | Весь диалог внутри окна, длинные поля доступны прокруткой |
| Поиск и клавиатура | Переход к найденной/редактируемой ячейке не прокручивает документ |
| Вход в настройки при выбранной последней ячейке | Изменение высоты таблицы сохраняет доступность выбранной ячейки |
| Первый запуск и сообщение автоматического открытия | Форма, нижние действия и рабочая область ограничены окном |
| Сохранение и повторное открытие | Пустое значение и 0 различаются, данные и подпись не потеряны |

Геометрия проверяется по `getBoundingClientRect()` и клиентским размерам документа,
а не по наличию CSS-правил. Снимки реального окна сохраняются как свидетельства CI.
Проверяется также видимость и попадание указателя в последние числовые ячейки
основной и вспомогательной таблиц после перехода к ним, а не только границы контейнера.
На узком экране закрепление сокращается до помещающегося префикса идентификаторов;
колонки, их сохранённые ширины, порядок и значения не удаляются и не изменяются.
`test_window_health.py` дополнительно проверяет, что нарушение границ останавливает
проверку выпуска и явно сообщает причину.
`test_window_geometry.py` проверяет преобразование физической рабочей области
в логические координаты, минимум окна и размещение при 100/125/150/200%.
Это тест вычисления геометрии; он не заменяет выполнение Windows с таким DPI.
Нативная проверка выпуска переходит к последней ячейке каждого из двух блоков,
проверяет видимую площадь и попадание указателя, затем восстанавливает выбранную
координату без редактирования данных.

Фактические результаты Linux/browser и Windows CI фиксируются в протоколе передачи
конкретного ZIP после выполнения. Windows 10/11, фактический масштаб 125/150/200%,
Windows Excel и пользовательская приёмка остаются отдельными проверками.
