# dev.30 — автоматическое открытие и объяснение ячеек

Основание: указание владельца 25.09.2026 и три фотографии из архива
archive-2026-09-25_20-08-17.zip. Фотографии содержат рабочие реквизиты и в Git не включены.
Решение: [ADR-0020](../decisions/ADR-0020-automatic-open-and-cell-guidance.md).

## Изменения

- Запуск на настроенной учётной записи Windows открывает отчёты без выбора личности.
  SQLCipher-ключ защищён DPAPI CurrentUser; личные коды и ключи подписи не запоминаются.
- При обновлении прежней зашифрованной базы один раз требуется её действующий код
  проверяющего/администратора. Он также нужен после переноса, если обёртка Windows
  недоступна. Создание нового администратора остаётся только первичной настройкой.
- Автоматическое открытие не создаёт личную или административную сессию.
  Сохранение, подпись, печать и административные изменения продолжают требовать код.
- Неизменяемые реквизиты, расчёты, сводки и недоступные для ввода значения имеют
  подсказки с объяснением источника и места ввода. Подсказка появляется при наведении
  или фокусе, закрывается Escape и помещается в окно, включая размер 1024×768.
- Формулы backend, порядок строк/столбцов, пустота/ноль, PDF-файлы и их шрифты прежние.
- Проверка поставки отвергает .device.json и его копии/временные файлы вне data,
  как и .keys.json. Пользовательские файлы не включаются в ZIP.

## Проверки доступа

1. Создать учебную базу, сохранить точные данные, закрыть программу.
2. Запустить новым процессом: сразу рабочий отчёт, значения прежние, current_user null.
3. Прямым IPC без кода проверить запрет записи/печати и создания ответственного.
4. Ввести неверный код сохранения: черновик остаётся, рабочие факты не меняются.
5. Прежняя база без DPAPI-файла: один корректный код, затем повторный запуск без входа.
6. Чужой/битый/потерянный DPAPI-файл не должен стирать или подменять базу.
7. Pending setup не должен открываться автоматически; чужой ключ другой базы отвергается.
8. Новые ответственные не должны ломать следующую автоматическую загрузку.
9. Проверить настоящий DPAPI и subprocess на Windows, а не только тестовую подстановку.

## Проверки подсказок

На всех трёх вкладках проверить: статичные реквизиты, планы только для чтения,
процент выполнения, накопительные/месячные итоги, склад, расход, дефицит и
готовые комплекты. Пустой результат объясняет недостающие источники и где их
вводить; заполненный — смысл и источник. У дочернего общества начальный остаток
находится в нижнем блоке «Данные для расчёта», месячное поступление — в матрице.
Ноль не считается отсутствующим. У формулы без настройки источник — настройки,
а не предложение вписать число непосредственно в расчётную ячейку.

Проверить hover и фокус, Escape, прокрутку, края окна 1024×768/1440×900;
переключение вкладок и сохранение не должны оставлять висящие подсказки.
Проверить прежние иконки доступных действий и baseline печатных файлов.

## Ограничения

Автоматическое чтение доступно текущей учётной записи Windows. DPAPI не защищает
от вредоносного ПО в её контексте. Для переноса нужна согласованная пара БД/.keys.json
и действующий код; .device.json не является универсальным ключом. Сброс кодов не добавлен.
Windows CI проверяет конкретную ОС/масштаб; все Windows 10/11 и корпоративные EDR
требуют отдельных испытаний. Собственные технические логи не включены; системные
следы Windows не исключаются.
