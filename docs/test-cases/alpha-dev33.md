# dev.33 — сохранение, восстановление и интеграция Excel

Основание: ADR-0022 и требования владельца от 26.09.2026. Версия остаётся проверочной.
В репозитории используются синтетические данные; исходные книги предприятия, их значения,
личные коды, базы и резервные комплекты в Git не включаются.

## Реализованные изменения

Защищённые команды desktop API создают согласованный комплект копии до записи и после
успешного изменения. Комплект публикуется атомарно после проверки файлов и контрольных сумм.
Восстановление проверяет комплект и создаёт новую папку; рабочая БД не перезаписывается.
Исторические копии не удаляются автоматически. Черновик интерфейса и полный дамп памяти
не входят в резервную копию БД.

Сервер классифицирует реквизиты, структуру, вводимые значения, формулы, контрольные итоги
и оформление. Интерфейс не ищет количества по номеру строки или по внешнему виду числа.
Согласованный предпросмотр содержит соответствия, структурные действия и счётчики.
Редактирование соответствия отменяет готовность пакета до повторной проверки.
Подтверждение выполняется для пакета целиком; массового автоматического исключения нет.

Собственный формат v2 передаёт структуру, идентичность, шапку, планы, периоды и значения;
чтение v1 сохраняется. Режимы: создать, дополнить, обновить. Пустое значение по умолчанию
сохраняет имеющееся; ноль переносится явно. Структура и значения фиксируются атомарно,
с проверкой актуальности исходного состояния. Складские недельные поставки и расход
остаются разными показателями.

Смена кода, отзыв действующего доступа и передача единственной административной роли
не удаляют историю подписей. Исправлены защита незавершённого ввода исходной книги
и включение всех несохранённых значений в пересчёт после отказа записи.

## Ограничения и уточнения

- Неделя без точных дат не сопоставляется по номеру. Пользователь указывает границы
  и основание для исходного столбца; несовместимость с рабочим календарём остаётся ошибкой.
- Неизвестные скрытые листы требуют явного решения. Исключение требует причины.
- Поддерживается ограниченный набор локальных формул. Неподдерживаемая формула,
  внешняя ссылка, цикл или ошибка вычисления не превращаются в ноль.
- Неоднозначность идентичности и отличающийся шаблон требуют проверки; универсальное
  распознавание любых Excel-книг не заявляется.
- Прежние незашифрованные копии не шифруются задним числом. При восстановлении нужен
  действующий для выбранного комплекта код; настройка Windows не заменяет файл ключей.
- Память интерфейса до сохранения не является резервируемыми данными.

## Приёмочные сценарии

| Сценарий | Ожидаемый результат |
|---|---|
| Отказ копирования до записи | Значения не изменены; понятная ошибка. |
| Отказ копирования после записи | Сохранение не выдаётся за откат; видимое предупреждение. |
| Неполный комплект или повреждённая контрольная сумма | Восстановление отклонено; исходные файлы не изменены. |
| Восстановление исправного комплекта | Новая папка; прежняя рабочая база остаётся на месте. |
| Ошибка последнего действия импорта / конфликт версии | Полный откат; новая проверка перед повтором. |
| Книга v1 с пустыми вводимыми полями | Заполненные рабочие значения сохранены. |
| v2: 100 остаток, 20 поступление, 5 расход | При определённых входах остаток первой недели: 100 + 20 − 5 = 115. |
| Повтор того же содержимого и назначения | Дубликаты не создаются. |
| Процент, контрольный итог, текстовый код | Не превращаются в вводимое количество. |
| Неизвестная неделя, скрытый лист, неподдерживаемая формула | Конкретное требование уточнения/ошибка, без молчаливого пропуска. |
| Изменение активной ячейки исходной книги без blur | Переход и закрытие защищены контролем несохранённого ввода. |
| Отказ сохранения 20, затем ввод 3 в соседнюю ячейку | Пересчёт получает оба несохранённых значения. |
| Смена кода / отзыв / передача роли | Старые полномочия не действуют; история подтверждений остаётся. |

Числа в сценариях специально заданы для проверки и не взяты из частных книг.

## Проверки выпуска

`npm run typecheck`, `npm test`, `npm run build`, pytest, статические проверки репозитория,
self-test упакованного приложения, реальное окно и повторное открытие новым процессом.
Окончательные результаты и ограничения фиксируются для конкретного commit в сообщении
выпуска/CI. Само наличие сценария не подтверждает его выполнение. Приёмка Windows 10/11,
масштаба экрана и политик рабочего места выполняется отдельно.
