# Проверки dev.7 и сравнение интерфейсов A/B

## Изменения

Числовые столбцы: ширина по умолчанию и минимум 84 CSS px вместо разрешённого
минимума 48. Сохранённые значения меньше 84 ограничиваются при отображении,
более широкие настройки сохраняются. Перенос чисел запрещён CSS. Маркер состояния
перенесён влево, отдельно от числа справа. Исходные значения и backend не меняются.

Основные кнопки и кнопки действий в настройках имеют минимум 44 px высоты и
видимые подписи. Шпаргалка открывается внутри настроек позиции; закрытие другого
окна не требуется. Предусмотрены копирование, ручное выделение при недоступном
буфере и вставка в выбранный показатель. Вставка блокируется при прямой ссылке
на себя и отсутствующих кодах. Проверка цепочек зависимостей остаётся на backend.

Библиотека показывает формулы подходящих наборов из
resources/report-definitions/presets/field-presets.v1.json и шаблоны с выбранными
кодами: CUMSUM, ROUNDDOWN, разность и BALANCE. Для комплектности нужна положительная
норма. Полные наборы Excel можно по-прежнему применять кнопками над библиотекой.
Общий PositionFieldsEditor обслуживает DAILY_MOVEMENT, HEAD_SITE и SUBSIDIARY.

| Перенос числа | Не запрещён | Запрещён |

Источники размеров: ColumnResizeHandle.tsx, ReportMatrix.tsx и kanban-layout.css
в соответствующих версиях. Размер 84 — выбранный запас для пяти цифр с отступами
и маркером, не результат измерения в WebView2. Для проверки мышью использован
ориентир [WCAG 2.2, Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html):
минимум 24×24 CSS px с предусмотренными исключениями. Размер кнопок сам по себе
не доказывает соответствие всей программы WCAG.

## Автоматические сценарии

- 23 frontend-теста: прежние 19 плюс три сценария библиотеки по типам отчётов
  и один сценарий ограничения старой ширины и клавиатурного изменения.
- Библиотека: скопирован точный текст, вставка не закрывает настройки, результат
  сохраняется, прямая ссылка на себя заблокирована, отказ clipboard обработан.
- Прежние проверки Excel, изображений, настроек, календаря и ввода сохранены.
- TypeScript, production build, offline policy и обязательные gates репозитория.
- Backend и форматы данных не редактировались; прежний набор 225 тестов.

Настоящий рендеринг WebView2, DPI, контраст всех состояний и полный клавиатурный
аудит не подтверждены DOM-тестами. Windows self-test проверяет упакованный EXE,
но не рисует окно. Нельзя утверждать, что пользователи стали работать быстрее.

## Протокол пользовательского A/B-теста

Использовать отдельные папки dev.6 и dev.7 с одинаковыми копиями учебной базы.
Для первой половины участников порядок A→B, для второй B→A. Не подсказывать
расположение действий. Участники должны впервые работать с программой.

Одинаковые задания в обеих версиях:

1. Внести 99999 и расход 12345, прочитать остаток и сохранить.
2. Расширить столбец мышью, затем изменить ширину клавиатурой.
3. Найти настройки, переместить показатель и переименовать позицию.
4. Назначить накопительный итог по существующему показателю, сохранить и проверить.
5. Повторить настройку на головной площадке и в дочернем обществе.
6. Выгрузить Excel и найти импорт этой книги.

Для каждой попытки записать: участник, порядок, вариант, задание, время в секундах,
успех без помощи, число ошибочных действий, обращения за помощью, комментарий.
Успех = правильный результат без подсказки; доля успеха = успешные / все попытки.
Сравнить долю успеха, медиану времени успешных попыток и ошибки по каждому заданию.
Оценить также 100%, 125% и 150% масштаба Windows, обычное и развёрнутое окно.

Результаты участников пока отсутствуют. Численность для статистического вывода
нужно определить по ожидаемому эффекту и исходным данным; небольшой ручной прогон
использовать только для выявления неудобств. Следующий шаг — собрать наблюдения
по этому протоколу и исправить подтверждённые затруднения.
