# Перенос экранного оформления по Frontend Reference Kit

Статус: профиль исходного состояния проверен; результаты выполнения проверок фиксируются
отдельно от требований. Область изменения — экранный frontend dev.29. Основание:
[ADR-0019](decisions/ADR-0019-reference-frontend.md) и прямое указание пользователя
сохранить шрифты печатных отчётов.

## Источники и проверка происхождения

Исходная программа: dev.28, commit `35e4e6968917b3df5d5de59705caa116620be3bf`.
Состав frontend и версии проверены по `package.json`, `frontend/src/main.tsx`,
`frontend/src/app/App.tsx`, `backend/desktop/launcher.py`.

Образец: пользовательский архив `Frontend_Reference_Kit_v1(2).zip`, SHA-256
`f2efa57c925e51d784b7c9f7caf6f5249058a776867e889a28bfb703fc1fe953`.
Внутри находится комплект v1.0.0 и неизменённый исходный снимок «Реестра писем».
Это конкретный приложенный снимок, а не заявление о последней версии его репозитория.

Команда `python tools/verify_package.py` в распакованном комплекте завершилась `passed`:
проверены 375 файлов манифеста, 206 исходных файлов и 9922 ссылки на исходники.
Числа взяты из результата этого проверяющего скрипта. Они подтверждают целостность
комплекта, но не работоспособность целевой программы.

[provenance.json](../config/frontend-reference/provenance.json) фиксирует исходный архив,
его контрольную сумму, результат проверки и SHA-256 исходных снимков dev.28.
Снимки `window-1.png`, `window-2.png`, `window-3.png`, `window-4.png`,
`window-head-header.png`, `window-settings.png` получены из Windows CI dev.28,
run `35501408519`. В репозиторий пользовательские изображения и рабочие базы не копируются.

## Стратегия и границы

Сохраняется существующая связка React 18 + TypeScript + PyWebView + Fixed WebView2.
Переносятся экранная палитра, Golos Text из локальных файлов, иерархия текста,
поверхности, формы, кнопки, таблицы, модальные окна и их состояния.
Параметры экрана подключаются через действующие стили frontend; JSON-профиль ниже
является спецификацией и не изменяет приложение сам по себе.

Не переносятся ядро Tauri, БД, парсер 1С, карточки писем, статусы документооборота
или таймлайн образца. Производственные матрицы, координаты ячеек, даты по горизонтали,
порядок обязательных строк, точные расчёты, права, шифрование, подписи и запуск
остаются частью существующей программы.

| Экран | Образец оформления | Сохраняемое поведение |
|---|---|---|
| Ежедневный отчёт | Таблица, панель действий, вкладки | Выбранный месяц, дни и единственный накопительный итог |
| Головная площадка | Группы строк, поля, таблица | План/факт, коды выпуска и компактная строка изделия |
| Дочерние общества | Группы строк, поля, таблица | Поставщики, недели, расход, договор и отклонения |
| План и сведения | Поля редактирования и панель действий | Изделие, коды, планы; личное подтверждение ответственного |
| Ответственные лица | Таблица и форма | Единственный администратор, несколько других ответственных |
| Настроить рабочее поле | Модальное окно и поля | Структура, связи и формулы; существующие права |
| Открытие программы | Карточка и форма кода | Подготовка/открытие защищённой базы |
| Подтверждение | Модальное окно и форма кода | Автоматический запрос при сохранении/печати; отмена сохраняет черновик |
| Как заполнить | Пошаговое модальное окно | Три шага, пропуск и повторный просмотр |
| Импорт Excel | Проверка и предпросмотр | Данные не изменяются до подтверждения |
| Импортированный отчёт | Таблица и панель действий | Листы, объединения, исходные формулы и экспорт |
| Сопоставление полей | Поля и фильтр | Явное сопоставление показателя/периода и причина исключения |

Полные источники полей, действий и статусов приведены в
[target-mapping.json](../config/frontend-reference/target-mapping.json).
[Профиль](../config/frontend-reference/target-profile.json) имеет статус `verified`
только в смысле проверенной инвентаризации кода. Это не статус завершённой приёмки.

## Иконки и доступность действий

Иконка сопровождает текст, когда ускоряет узнавание действия: сохранить, печатать,
импортировать, экспортировать, изменить, добавить, удалить, открыть настройки,
помощь или раздел ответственных. «Ещё» и раскрываемые блоки показывают направление
раскрытия и передают `aria-expanded`; знак печати является принтером.

Текстовые кнопки «Отмена», «Пропустить», цифровые переключатели и подписи выбора
не обязаны содержать значок. Значок не заменяет доступное имя действия. Для
иконок без текста требуется понятный `aria-label` или эквивалентная подпись.
Декоративные SVG скрыты от повторного озвучивания, локальны и не загружаются из CDN.

Проверяется не только наличие SVG, но и смысл кнопки, сохранность доступного имени,
обработчика, состояния disabled/busy и запрета повторной операции. Ошибка не должна
выглядеть как успех; один цвет не является единственным обозначением статуса.

## Печатные отчёты

Экранный шрифт Golos Text не назначается шрифтом PDF. Текущие генераторы
`backend/infrastructure/monthly_pdf.py`, `backend/infrastructure/subsidiary_pdf.py`
и файлы `resources/fonts/ReportingSans.ttf`, `ReportingSansBold.ttf`,
`ReportingSerif.ttf` защищены контрольными суммами в
[print-baseline.json](../config/frontend-reference/print-baseline.json).

Для этой задачи они должны оставаться побайтно равны dev.28. Это включает существующие
размеры, начертания, подписи и алгоритмы размещения. `minimum_font: null` в профиле
означает, что задача не вводит новый порог, а не отсутствие требования к читаемости.
Исходный `reference-full.css` и печатные CSS образца не подключаются целиком.
Проверка неизменности файлов дополняется регрессией генерации PDF и Windows-печати.

## Конфигурация и обоснованные отличия

В `config/frontend-reference/` находятся профиль, сопоставление, отклонения,
происхождение, контрольные суммы печати и чек-лист приёмки. Три JSON-схемы скопированы
из комплекта без изменения; ссылки `$schema` ведут на локальные `schemas/`.
Цветовые значения не дублируются в этом профиле: он ссылается на роли темы.

[deviations.json](../config/frontend-reference/deviations.json) явно сохраняет:

- собственные PDF и шрифты вместо печатного образца;
- матрицы производственной отчётности вместо реестра писем;
- существующие WebView, хранение и portable-сборку;
- производственные статусы и действующие права;
- подходящие действиям локальные SVG, включая отсутствующие в образце;
- ширины числовых колонок, прокрутку и закрепления, необходимые отчётным таблицам.

Эти отличия следуют текущей задаче и требованиям программы; изменение бизнес-модели
для визуального сходства не требуется.

## Проверки и свидетельства

[acceptance-checklist.json](../config/frontend-reference/acceptance-checklist.json)
разделяет требования и результаты. `not_run` означает отсутствие завершённого
свидетельства именно этой проверки; наличие тестового файла не считается успехом.
Фактические команды, результаты и ограничения инкремента помещаются в
[alpha-dev29.md](test-cases/alpha-dev29.md), а идентификаторы итоговых CI-запусков,
снимки окна и ссылка ZIP — в описание PR/релиза.

Обязательные проверки инкремента:

1. Валидация трёх профилей по локальным JSON-схемам и проверка существования путей.
2. Сравнение защищённых печатных файлов с SHA-256 dev.28.
3. TypeScript, frontend-тесты и сборка; семантическая проверка иконок действий.
4. Backend-регрессия расчётов, 0/пусто, прав, подтверждения и импорта/экспорта.
5. Сценарии реального Windows-окна: открытие, ввод, подтверждение, три отчёта,
   настройки, прокрутка и PDF; визуальная оценка полученных снимков.
6. Проверка локальных ресурсов, состава portable ZIP, путей хранения и автономного запуска.

Нельзя считать изображение доказательством клавиатурной доступности, а запуск на
Windows CI — испытанием на всех вариантах Windows 10/11 и всех масштабах ОС.
Проверенные размеры и масштаб указываются только после фактического измерения.
