# Версионируемые дескрипторы матриц

Статус: `WORKING_REFERENCE` — технический preview, не утверждённая карта импорта.

## Назначение

Дескрипторы в `resources/report-definitions/` фиксируют минимальную структуру трёх
матричных форм, подтверждённую `AGENTS.md` и DEV v0.5. Они нужны для ранней сборки и
визуальной проверки frontend без переноса скрытых наименований, реальных кодов или
сомнительных формул из рабочих Excel-файлов.

Каждый файл содержит отдельные версии схемы и определения. Изменение порядка блоков,
строк или колонок требует новой версии дескриптора и протокола различий с эталоном.

## Дескрипторы

| Report type | Файл | Зафиксировано |
|---|---|---|
| `DAILY_MOVEMENT` | `daily-movement.working-reference.v0.1.0.json` | 31 календарная колонка дня месяца; компонентные строки `Получено` → `Использовано` → `Остаток`; строки сборочного комплекта и готового изделия; нижний складской блок и готовые комплекты |
| `HEAD_SITE` | `head-site.working-reference.v0.1.0.json` | группы изготовитель/поставщик → комплект/изделие; `План` перед `Фактом`; календарная ось, создаваемая для выбранного периода; месячные и накопительные итоги |
| `SUBSIDIARY` | `subsidiary.working-reference.v0.1.0.json` | изготовитель/поставщик → изделие/ДСЕ/ПКИ; договорной/годовой объём; утверждённый план; горизонтальные периоды; поставка накопительно, отклонение и профицит/дефицит |

Файл `resources/schemas/report-definition/matrix-definition.schema.json` проверяет
общий формат этих определений.

## Ограничения

- Все идентификаторы с префиксом `wrk-` синтетические и не имеют бизнес-смысла.
- `binding.status = OPEN` означает, что постоянный `metric_code`, `operation_type`,
  ключ справочника или координата импорта не утверждены.
- `WORKING_INPUT` означает только предусмотренное исходной формой место ввода. Это не
  утверждение роли, права, источника факта или способа сохранения в БД.
- Дескрипторы не содержат Excel-адресов и не могут использоваться для импорта или
  экспорта без отдельной утверждённой координатной карты.
- Число недель/дат в форме дочернего общества остаётся `OPEN`; колонки создаются во
  время выполнения после выбора утверждённого типа периода.
- Синтетические подписи `Позиция 1`, `Сборочный комплект 1`, `Готовое изделие 1` и
  `Изделие/ДСЕ/ПКИ 1` не заменяют реальные справочники.
- Пустая ячейка и подтверждённый ноль остаются разными состояниями. Дескриптор не
  определяет способ сохранения подтверждённого нуля в журнале ненулевых операций.

## Условия перехода к `APPROVED`

Для каждого типа формы владелец процесса должен подтвердить контрольную сумму и версию
эталона, владельца формы, реальные бизнес-ключи, карту ввода/импорта/расчёта, правила
пустого значения и нуля, точность, периодизацию, экспорт и допустимые изменения
оформления. До этого дескрипторы должны загружаться только как технический preview.
