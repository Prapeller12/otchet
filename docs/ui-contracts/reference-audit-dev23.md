# Ревизия соответствия форм — dev.23

Дата: 19.09.2026. Основание: прямое указание владельца программы повторно сверить
все рабочие поля с предоставленными образцами. Исходные книги, изображения,
наименования, значения и внутренние ссылки остаются вне публичного репозитория.

## Как читать контракт

Эталон определяет состав полей, их порядок, группы и ось времени. Ранее явно
исправленные владельцем формулы сохраняются. Ошибочные формулы, несовпадающий
год заголовка и месячных колонок, случайное закрепление ячеек исходной книги не
переносятся. Пустое значение по-прежнему отличается от подтверждённого нуля.

Статус этого документа — проверенная карта требований. Перечень обнаруженных
различий не означает, что каждое из них уже реализовано. Фактический состав
исправлений и проверки фиксируются в протоколе выпуска dev.23.

## Дочерние общества

| Область | Поля и порядок | Правило |
|---|---|---|
| Шапка | Период, годовой план/итог, текущий месячный план, завод/объект, изображение готовой части, дата состояния | Одна готовая составная часть на отчёт |
| Идентификация | Изображение, номер, обозначение, наименование, входимость, производитель | Одна деталь может объединять несколько производителей |
| Сводные поля | Начальный остаток, складской остаток, договорной объём, месячные поступления, общий дефицит/профицит | Поступления и договор индивидуальны; остатки и материальный дефицит общие по детали |
| Ось времени | Месяцы слева направо, внутри месяца недели | Недельная ячейка — расход, согласно ADR-0013 |
| Дополнительное отклонение | Недопоставка/перепоставка по договору | Не подменяет общий материальный дефицит; требует отдельной подписи и периода |

Сводные поля выбранного месяца должны однозначно показывать месяц и дату
остатка. Повторение четырёх сводных колонок в каждом месяце отличается от
исходной структуры с отдельной областью сводки перед недельной осью.

## Головная площадка

| Область | Поля и порядок | Правило |
|---|---|---|
| Шапка | Период, общий план/факт, шифр изделия, завод, изображение изделия, дата состояния | Шифр и изображение изделия отличаются от обозначений и изображений его частей |
| Выпуск по кодам | Упорядоченные строки кодов/модификаций, годовой факт, пары «План» → «Факт» для месяцев | Названия кодов задаёт пользователь; связь кодов с ежедневной формой не угадывается |
| Идентификация частей | Изображение, номер, обозначение, наименование, входимость, контрагент | Общие поля объединены по производителям одной части |
| Сводка частей | Начальный остаток, склад, изготовлено накопительно, расход, дефицит/профицит; договор отдельно при необходимости | Изготовлено накопительно — фактическое количество, а не введённое обязательство по договору |
| Ось времени частей | Месяцы слева направо, внутри каждого «План» → «Факт» | Инвентарные показатели не заменяют пары плана/факта |

Исходная подпись показателя текущего месяца не совпадает с его формулой.
В фиксированной сводке «Изготовлено в месяце» означает фактическое изготовление
выбранного месяца; оно может повторять его календарную ячейку «Факт». Отдельный
показатель «Дефицит / профицит» использует утверждённую формулу ADR-0015:
начальный остаток + факт производителей − план производителей. Расход готовых
изделий повторно в эту формулу не включается. План части уже выражен в штуках части.

При добавлении детализации верхнего выпуска по кодам существующие суммарные
планы и факты нельзя молча перезаписать. Нужны явная совместимость и проверка
согласованности; автоматическая связь с ежедневными данными не утверждена.

## Ежедневный отчёт

| Область | Поля и порядок | Правило |
|---|---|---|
| Движение материалов | Изготовитель/поставщик, позиция; «Получено» → «Использовано» → «Остаток» | Допускаются отрицательные корректировки движения |
| Контекст периода | Сводные данные года, итоги предыдущих месяцев, календарные дни выбранного месяца | Для остатка берётся состояние на конец периода, а не сумма дневных остатков |
| Сборочный комплект | Планы по кодам, затем фактический выпуск по кодам, отправка, прибытие | Количество кодов и подписи настраиваются; скрытые названия не восстанавливаются |
| Готовое изделие | План/факт по кодам, отправка, прибытие | Матричный ввод сохраняется |
| Склад | Остатки по кодам/модификациям и комплектность | Подписи редактируются согласно dev.21 |
| Нижняя месячная таблица | Месяцы, получено, использовано, остаток; итог | Составные части дочерних обществ; не смешивать с верхним блоком ПКИ |

Единственная строка «Выпущено по кодам» без настроенных строк каждого кода не
заменяет детальную структуру образца. Печатная сводка прошлых месяцев не заменяет
соответствующие рабочие поля, если они отсутствуют в основной таблице.

## Границы архива

В комплекте также есть реестр зарегистрированных документов: номер, дата
регистрации, регистрационный номер, вид, наименование, организация и плановый
срок. Это отдельная форма документооборота, а не один из трёх производственных
отчётов. Она не импортируется в производство и не образует новую вкладку без
отдельного решения владельца.

## Обязательные проверки

- Порядок групп, полей и периодов в рабочей форме, Excel и PDF.
- Общие поля детали и индивидуальные поля производителя при нескольких
  производителях и при наличии архивной строки с историческими значениями.
- Независимость договорного отклонения и материального дефицита.
- Правильное суммирование выпуска по кодам, сохранность ранее введённых итогов.
- Пустое значение, подтверждённый ноль, отрицательная корректировка движения.
- Клавиатурный ввод, прямоугольная вставка и сохранение положения таблицы.
- Читаемость пятизначных количеств и длинных подписей; отсутствие обрезанного
  текста при печати; блок криптографического подтверждения не более двух строк.
