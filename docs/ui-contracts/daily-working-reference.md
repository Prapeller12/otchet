# Ежедневная матрица: рабочая фиксация

Статус: `WORKING_REFERENCE`, не утверждённый эталон.

## Обязательная структура

По разделам 4.2 и 5.1 `AGENTS.md` сохраняются:

- календарные даты месяца по горизонтали слева направо;
- изготовители, поставщики, позиции, сборочные комплекты, ДСЕ и ПКИ по вертикали;
- для позиции порядок `Получено` → `Использовано` → `Остаток`;
- для сборочного комплекта и готового изделия порядок `План выпуска` → `Выпущено по
  кодам` → `Отправка` → `Прибытие`;
- нижний складской блок по кодам/модификациям и готовым комплектам;
- ввод непосредственно в разрешённых ячейках матрицы; расчётные ячейки не редактируются.

По решению владельца от 02.09.2026 сумма вводимой строки и признак расчётного показателя
выводятся внутри закреплённой колонки `Показатель`, а не повторяются маркерами в календарных
ячейках. Это изменение представления не переносит календарные даты с горизонтальной оси.

Изготовитель/поставщик и позиция настраиваются в отдельном окне. Добавление позиции создаёт
полную обязательную группу показателей соответствующего типа; отдельные обязательные
показатели внутри группы не удаляются.

Предоставленные материалы используются только для внутренней сверки и не копируются в
публичный Git-репозиторий.

## Отдельный расчётный источник

Расчётный пример не является визуальным эталоном формы. Из него переносится только
проверяемая логика готовности, уже зафиксированная в `AGENTS.md` и DEV v0.5:

```text
available_sets_i = floor(available_qty_i / qty_per_product_i)
ready_sets = min(available_sets_i)
```

Проверенные контрольные строки книги:

| Дата | Ограничивающее значение | Входимость | Расчёт | Результат |
|---|---:|---:|---:|---:|
| 18.03.2024 | 71 | 3 | `floor(71 / 3)` | 23 |
| 19.03.2024 | 90 | 3 | `floor(90 / 3)` | 30 |

В приложении эта логика реализуется в backend/domain с `Decimal`, а не копированием Excel-
формулы во frontend.

## Не переносить как бизнес-правило

- демонстрационные подписи не являются справочником реальных кодов;
- компоновка расчётного примера не меняет каноническую форму;
- ноль в примере не доказывает, что пустая ячейка равна нулю;
- вспомогательные формулы примера не определяют будущую структуру API или БД.

## `OPEN`

- точные бизнес-ключи строк и кодов;
- карта вводимых, импортируемых и расчётных ячеек;
- правила обязательности данных по дню;
- точность отображения и округление величин кроме готовых комплектов;
- правила экспорта и печати.
