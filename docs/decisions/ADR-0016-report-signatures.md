# ADR-0016: Криптографическая верификация отчётов

Статус: ACCEPTED — прямое указание владельца от 19.09.2026: добавить
верификацию пользователем и криптографические ключи по образцу production-cycle,
печатный блок не более двух строк.

Прежняя отметка с вручную введённым ФИО не удостоверяла владение ключом.
Для трёх месячных отчётов вводятся постоянные ключи пользователей Ed25519.
Закрытый ключ защищён PIN через Argon2id и ChaCha20-Poly1305; PIN не сохраняется.
Первый профиль — администратор ключей; создание следующих требует его PIN.
Эта роль управляет только профилями подписантов, не расширяет права работы с данными.

Подписываются UUID события, UTC-время, профиль/ФИО, полный открытый ключ,
организация, тип и период отчёта и SHA-256 канонического снимка.
Подпись проверяется backend при чтении статуса и при PDF-экспорте. Несовпадение
снимка означает STALE; нарушение подписи или полей — INVALID. Старые отметки
сохраняются как LEGACY, без заявления о криптографической проверке.
Повтор того же подтверждения тем же ключом идемпотентен, но также требует PIN.

Миграция 0012 добавляет профили и подписи, не изменяя исторические строки 0008.
Записи неизменяемы; снимок и подпись записываются одной транзакцией после проверки
актуальности данных. UI выбирает профиль и запрашивает PIN на каждую подпись.
Общий PDF-блок из двух физических строк: статус/ФИО/время и ключ/подпись Base64.
Закрытый ключ не попадает в IPC-ответы или PDF. Сохраняется прежняя матрица.

В portable ZIP добавляется библиотека cryptography вместе с её runtime-зависимостями;
у пользователя установка не требуется. Внешние сетевые сервисы не используются.
Реализация криптографии следует API PyCA, алгоритмы соответствуют проекту-образцу:
https://github.com/Prapeller12/production-cycle/blob/d28140a07cd6520a28e6fb7cbdd521e736b0b63b/docs/signed-audit-log.md
https://cryptography.io/en/latest/hazmat/primitives/asymmetric/ed25519/
https://cryptography.io/en/latest/hazmat/primitives/key-derivation-functions/

Границы: локальные профили не удостоверяют паспортную личность. Это внутренняя
подпись данных, не КЭП и не PDF/PAdES-подпись всего файла. Полная подмена/откат
базы вместе с ключами не обнаруживается без независимой доверенной копии.
PIN нельзя восстановить; база с ключами должна входить в защищённые резервные копии.
Полный журнал всех сохранений production-cycle не переносится: запрос относится
к подтверждению отчёта пользователем.

Откат: восстановить резервную копию, созданную перед миграцией, в отдельной папке
предыдущей версии. Старый EXE не запускать на новой рабочей базе.
Проверки: миграция старой базы, неверный PIN, администратор, неизменяемость,
подмена снимка/подписи/метаданных, устаревание, все три PDF, две строки,
перезапуск, packaged Windows self-test и UI-сценарий.
