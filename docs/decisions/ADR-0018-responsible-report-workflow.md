# ADR-0018: Работа ответственных и подтверждение при сохранении

Статус: ACCEPTED — прямые требования владельца по шести снимкам экрана от 20.09.2026.

## Решение

Все три ответственные роли (руководитель проекта, проверяющий, администратор)
могут менять значения, планы, название отчёта и сведения об изделии, подтверждая
запись собственным кодом. Доступ к этим полям открывается через «План и сведения».
Структура форм, организации, импорт и управление пользователями остаются у
единственного администратора. Открытие зашифрованной базы сохраняет правила
ADR-0017: администратор или проверяющий; ключ базы руководителю не выдаётся.

После проверки кода при входе в раздел администратора backend хранит только
идентичность администратора в памяти. Создание ответственного использует эту
сессию без повторного запроса кода. Выход из раздела, блокировка и завершение
программы прекращают сессию. Анонимное создание через прямой IPC запрещено.
Код администратора в сессии не сохраняется.

В каждом отчёте рядом расположены «Сохранить» и «Печать / PDF A4».
Самостоятельная кнопка «Подтвердить данные» удаляется. При сохранении и печати
программа запрашивает личный код ответственного один раз и объясняет, что
действие подтверждает проверку данных. Backend проверяет код до записи.
После успешной записи строится новый канонический снимок выбранного периода
и подписывается Ed25519 тем же ключом. Печать подтверждает актуальный сохранённый
снимок перед формированием PDF; несохранённые правки нужно сначала сохранить.

Сохранение значений и подпись используют существующие транзакции. Если запись
успела завершиться, но проверка согласованности не позволяет подписать отчёт,
ответ явно сообщает «Сохранено, но не подтверждено» и причину. UI не выдаёт
это за отменённую запись или успешное подтверждение. Неверный код и отмена
до записи сохраняют черновик без записи. Подпись никогда не относится к старой
версии до сохранения. Код живёт только в обработке текущего действия.

Навигация между тремя отчётами закрепляется при вертикальной прокрутке.
В ежедневном отчёте показаны даты только выбранного месяца и один столбец
«Накопительный итог»: с 1 января по конец выбранного месяца включительно.
Используется существующий backend through_month: потоки суммируются точно,
остатки берутся на последнюю дату, отсутствие данных не превращается в ноль.
Месячные и годовые данные не удаляются из базы или экспортных контрактов.

## Данные, API и переносимая поставка

Миграция0014 расширяет аудит доступа ролью руководителя проекта с сохранением
истории. Старые миграции и криптографические идентичности неизменны. Новые
параметры подтверждения относятся только к desktop facade; исходные команды
сохранения и канонические снимки остаются совместимыми. Формат ZIP, SQLCipher,
Fixed WebView2 и отсутствие внешней сети в программе сохраняются.

## Проверки и откат

Проверить все роли прямыми IPC, запрет управления пользователями без сессии,
выход из сессии, ровно одного администратора, отказ неверного кода, правильную
подпись после изменения, ошибку подтверждения после сохранения, печать и отмену,
накопительный итог/остаток/пустое/ноль, закрепление вкладок и настоящее окно Windows.
Откат к прежнему приложению — только вместе с сохранённой совместимой резервной
копией базы и файла ключей; применённые миграции не переписывать.
