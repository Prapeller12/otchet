# ADR-0022: резервирование сохранений и интеграция Excel

Статус: ACCEPTED
Дата: 26.09.2026
Основание: прямое поручение владельца исправить результаты аудита, создавать копию БД при каждом сохранении и выполнить требования документа Excel_import_changes.docx от 26.09.2026.

## Решение

Каждая команда сохранения desktop API создаёт проверенный согласованный комплект резервной копии до записи. Ошибка создания комплекта запрещает начало операции. После успешной записи создаётся копия нового состояния; ошибка этого этапа показывается как предупреждение о резервировании при успешном сохранении данных. Комплект содержит зашифрованную БД, соответствующую обёртку ключей и контрольные суммы. Незавершённый комплект не публикуется под именем готовой копии. Исторические копии автоматически не удаляются.

Excel проходит стадии: файл, распознавание, проверка, подтверждение и атомарная запись. Сохранение исходной книги отдельно не означает перенос в рабочую базу. Сервер классифицирует источники, периоды, формулы и структуру; интерфейс отображает этот единый результат. Неизвестный период, несовместимая единица и неоднозначная идентичность требуют явного решения. Проценты и контрольные итоги не становятся количеством. Пустое значение по умолчанию не очищает заполненную ячейку; ноль остаётся явным нулём.

Версия 2 собственного Excel-обмена включает идентичность набора данных, структуру, реквизиты, планы, периоды и значения. Чтение прежней версии сохраняется. Перестановка строк и совпадение локального ID из другой базы не разрешают молчаливое слияние. Структура, планы, факты и отметка проведения записываются одной транзакцией с проверкой актуальности предварительного результата.

Личные ключи и существующие криптографические подписи сохраняются. Управление действующим доступом отделяется от неизменной истории подписей: отзыв пользователя, смена кода и передача роли единственного администратора проверяются backend. Автоматическое открытие Windows не предоставляет личных полномочий записи.

## Границы

Привычные матрицы, порядок строк, правила расчётов и автономная Windows onedir-поставка сохраняются. Исходные книги пользователя и данные из них не публикуются в Git. Неизвестные бизнес-правила не восстанавливаются догадкой. Полный дамп памяти не является резервной копией БД и не включается по умолчанию.

## Приёмка

Регрессионные проверки импорта и сохранения включают отказ перед записью, отказ последнего действия пакета, отказ копирования ключей, повторный импорт, конфликт версии, пустоту и ноль, формулы, несопоставленные периоды, ввод без потери фокуса, пересчёт после ошибки сохранения. Проверяется повторное чтение после перезапуска и восстановление согласованной копии. Чистые Windows 10/11 требуют отдельной нативной приёмки; результаты CI указываются точно.
