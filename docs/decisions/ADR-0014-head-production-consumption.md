# ADR-0014: Расход составных частей и будущая связь с ежедневным отчётом

Статус: ACCEPTED — формула и подготовка интерфейса подтверждены владельцем в диалоге.

## Решение

Расход составной части = фактический выпуск готовых изделий × входимость.
План выпуска не подставляется вместо факта. Пустой факт остаётся неизвестным;
подтверждённый ноль даёт нулевой расход. Например, 1000 изделий × 4 шт. = 4000 шт.
Расчёт выполняется в backend с точной Decimal-арифметикой.

## Подготовленный интерфейс

`backend/application/production_consumption.py` принимает снимок выпуска
готового изделия и нормы составных частей с идентификаторами версий спецификации.
Снимок содержит организацию, изделие, начало и конец периода, тип исходного
отчёта и версию данных. Результат сохраняет эти сведения для проверки источника.

`ActualProductionReader.read_actual` — интерфейс будущего адаптера ежедневного
отчёта. `read_consumption` проверяет совпадение организации, изделия и периода.
`prepare_consumption` доступен для уже прочитанного снимка головной площадки.

Это вычисляемое представление без записи операций. Повторное чтение не изменяет
остатки. Сведения из головного и ежедневного отчётов нельзя суммировать, если они
описывают один выпуск. При подключении ежедневной формы нужно выбрать единственный
источник факта и заменить снимок расчёта, а не добавлять ещё одно списание.
Нельзя автоматически раскладывать месячный выпуск по дням.

## Границы реализации

Адаптер к ячейкам ежедневного отчёта ещё не подключён: его рабочая форма будет
дорабатываться отдельно по указанию владельца. Данный модуль не изменяет БД,
существующий матричный ввод, импорт, экспорт или portable-запуск.
Подключение новой матрицы головной площадки и настройки связи с дочерними
обществами остаются отдельной незавершённой частью текущей задачи.

## Проверки

Тесты проверяют точную арифметику, ноль и отсутствие факта, недопустимые нормы,
дубли составной части, повторное чтение, исправление факта и запрет смешивания
организаций, изделий и периодов. Проверка повторного чтения относится только к
этому модулю без записи, а не к ещё не реализованным транзакциям ежедневного отчёта.

Следующий этап: использовать этот расчёт в новой месячной матрице головной
площадки, затем реализовать уникальные связи с отчётами дочерних обществ.
