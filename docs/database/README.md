# База данных

Начальная SQLite-схема находится в `backend/migrations/0001_initial_schema.sql`, а защита
утверждённых версий BOM — в `backend/migrations/0002_freeze_approved_bom.sql`. Вместе они
покрывают только подтверждённое ядро: организационную область, изделия, компоненты,
версионируемый BOM и отдельные проведённые операции.

Подтверждено: SQLite применяется для локального MVP, PostgreSQL — для централизованного
режима; количества не хранятся как `float`; проведённые операции нельзя удалить или
редактировать, исправление выполняется связанным сторно; изменения схемы выполняются только
последовательными миграциями.

Состав, идентичность и период действия версии BOM после статуса `APPROVED` неизменяемы.
Версию можно только перевести в `RETIRED`; исправленный норматив оформляется новой версией.

Первичный журнал хранит `operation_at` как ISO 8601 timestamp с обязательным часовым поясом
(`Z` или `±HH:MM`) отдельно от `created_at`. Календарная `operation_date` в контракте
матричной ячейки является отчётной координатой и не заменяет время первичной операции.

`0003` добавляет неизменяемые ревизии фактов и бизнес-аудит, а `0004` — профили рабочих
организаций и архивируемые настройки строк матриц. Настройки структуры не смешиваются с
фактами и не удаляют их при скрытии позиции или дочернего общества.

Пока не реализованы таблицы пользователей, ролей, периодов, планов, договоров и staging-
импорта: их поля и права зависят от открытых решений владельца программы.
