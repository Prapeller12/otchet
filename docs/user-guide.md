# Руководство пользователя: «Производственная отчётность»

Редакция для dev.30. Руководство описывает рабочую форму программы; конкретные названия изделий, обществ, поставщиков и кодов задаёт пользователь.

## 1. Назначение и запуск

Программа предназначена для локального заполнения производственных отчётов, расчёта показателей, обмена Excel, подготовки PDF и подтверждения сохранённых данных персональным ключом. Основной способ работы — таблицы с периодами по горизонтали. Ввод не является проведением складских операций в бухгалтерской или ERP-системе.

1. Скачайте Windows x64 ZIP из раздела [Releases](https://github.com/Prapeller12/otchet/releases).
2. Полностью распакуйте архив в отдельную доступную для записи папку на локальном диске. Не запускайте EXE непосредственно из архива.
3. Запустите `start.cmd` либо `ReportingSystem.exe` из распакованной папки. Не перемещайте один EXE отдельно от остальных папок.
4. При первом запуске укажите ФИО единственного администратора и придумайте личный код от 6 до 128 символов. Повторите код и нажмите «Создать администратора и начать». Храните код отдельно от папки программы.
5. При следующих запусках на той же учётной записи Windows отчёты открываются без кода. При переходе со старой зашифрованной базы, переносе на другой компьютер или восстановлении настройки один раз потребуется действующий код проверяющего или администратора. Подробности — в разделе 9.
6. Пройдите три подсказки «Как заполнить»: выбрать отчёт → заполнить таблицу → сохранить с проверкой. Подсказки можно пропустить и открыть снова одноимённой кнопкой.
7. Выберите вкладку, организацию, год и месяц. Заполните данные и нажмите «Сохранить». Ответственный проверяет изменения и вводит свой личный код: подходит руководитель проекта, проверяющий или администратор.

Для готового ZIP не нужно отдельно устанавливать Python, Node.js, Microsoft Excel или браузер. В полную сборку включены Python-компоненты, frontend и WebView2 Fixed Runtime. Сборка рассчитана на Windows 10/11 x64; проверка конкретного выпуска на Windows указывается в его release notes. Рабочую базу нельзя размещать на сетевом/UNC-диске для совместного использования.

Источник: [переносимые пути и проверка конфигурации](../backend/desktop/paths.py), [запуск приложения](../backend/desktop/launcher.py), [проверки выпуска](../scripts/verify_release.py).

В dev.29 экран оформлен по Frontend Reference Kit: светлый фон, локальный шрифт Golos Text, красная кнопка основного действия. Иконки сопровождают понятные действия: дискета — сохранить, принтер — печать, стрелка — раскрыть «Ещё», шестерёнка — настройки. Текстовые подписи сохранены; выбирать действие только по рисунку не требуется. Шрифт и размеры текста в печатных отчётах не менялись.

## 2. Роли и интерфейсы

| Роль | Что разрешено |
|---|---|
| Руководитель проекта | Заполнять значения, планы и сведения об изделии, сохранять и подтверждать отчёты собственным кодом. На настроенном компьютере отчёты открываются автоматически. Первую настройку открытия прежней базы его код не выполняет. |
| Проверяющий | Настраивать открытие прежней базы своим кодом с разрешённым доступом, заполнять значения, планы и сведения, сохранять и подтверждать отчёты своим кодом. Проверяющих может быть несколько. |
| Администратор | Всё перечисленное, а также организации, структура форм, нормы, импорт Excel и создание ответственных лиц. Администратор ровно один. |

Это **три роли доступа**, а не очередь из трёх обязательных подписей. При каждом сохранении и печати требуется личный код ответственного. Создание нового пользователя в уже открытом разделе администратора не требует повторного ввода кода администратора.

Обычный экран **«Заполнение отчётов»** содержит таблицу, выбор периода и кнопки **«Сохранить»**, **«Печать / PDF A4»**, **«Ещё»**. Переключатель отчётов и организации закреплён при прокрутке. Для изменения названия отчёта, изделия, шифра и плана нажмите **«План и сведения»**. Этот экран доступен ответственным; запись требует их личного кода.

Для управления программой нажмите **«Администратор»** и введите его код. В отдельном разделе доступны:

- **«План и сведения»** — сведения и план выбранного отчёта;
- **«Настроить рабочее поле»** — организации, позиции, изготовители, нормы, строки и формулы;
- **«Ответственные лица»** — создание проверяющих и руководителей проекта.

В «Ответственных лицах» заполните имя, выберите роль, введите и повторите личный код нового пользователя. Нажмите «Создать ключ ответственного»: повторного запроса вашего кода здесь нет. Сообщите личный код его владельцу. Второго администратора создать нельзя. **«К заполнению отчётов»** завершает административный сеанс; для нового входа потребуется код.

### Общие правила заполнения

| Элемент | Как работать |
|---|---|
| Пустая ячейка | Данные ещё не представлены. Не заменяйте пустоту нулём автоматически. |
| `0` | Подтверждённое отсутствие количества. Вводите ноль только после проверки. |
| Вводимая ячейка | Откройте двойным щелчком или клавишей Enter, введите число. |
| Расчётная ячейка | Наведите указатель или перейдите к ячейке клавиатурой. Подсказка объяснит, откуда берётся результат и что заполнить. Прямой ввод запрещён. |
| Неизменяемое поле | Подсказка показывает, где изменить источник: «План и сведения», настройки рабочего поля или данные для расчёта. |
| Ячейка с ошибкой | Прочитайте пояснение, исправьте источник ошибки и дождитесь пересчёта. |
| «Сохранить (N)» | Записывает изменённые ячейки; N — их количество. На обычном экране через верхнюю кнопку сохраняется также изменённый месячный выпуск. |
| Окно подтверждения | Выберите ответственное лицо и введите его код. Для значений, плана и сведений подходит любая ответственная роль; для структуры и организаций — администратор. |
| Неверный код или отмена | Запись не разрешается; черновик остаётся на экране. Исправьте код или вернитесь к заполнению. |
| Сохранение шапки / плана | Измените поля в «План и сведения», затем нажмите верхнюю кнопку «Сохранить» и введите личный код. |

Подсказки появляются при наведении и фокусе клавиатуры, не обрезаются границами таблицы и закрываются клавишей Esc. Они доступны и для заполненного результата. Если в «Дочерних обществах» вместо склада показано «Заполните!», проверьте подсказку и блок «Данные для расчёта» ниже: начальный остаток вводится там, поступления — по каждому производителю в основной таблице. Ноль вводите только при подтверждённом отсутствии количества.

Стрелки перемещают выделение. Enter подтверждает ввод; Tab переводит к следующей доступной ячейке. При вставке диапазона из Excel сначала проверьте предпросмотр и только затем применяйте значения. Расчётные и заблокированные ячейки не становятся вводимыми при вставке.

В «Головной площадке» и «Дочерних обществах» через «Показать несколько месяцев» можно открыть дополнительные периоды. В ежедневном отчёте выбирается один месяц: видны его дни и один «Накопительный итог». Нажатие названия месяца раскрывает или сворачивает его столбцы. «Раскрыть все» показывает весь год. Ширину можно менять за границу заголовка; «Компактные столбцы: 5 цифр» возвращает компактную настройку. Сворачивание столбцов не удаляет данные.

Если переход на другую вкладку, организацию или в настройки заблокирован, завершите ввод и сохраните изменения соответствующего блока. Для шапки и месячного плана предусмотрены отдельные кнопки отмены. После сообщения об изменении формы другим сохранением перечитайте данные, прежде чем повторять ввод.

Источник: [матрица и сохранение](../frontend/src/widgets/report-matrix/ReportMatrix.tsx), [редактор ячейки](../frontend/src/widgets/report-matrix/CellEditor.tsx).

## 3. Организации, позиции, производители и нормы

Войдите в **«Администратор» → «Настроить рабочее поле»**. В этом окне выбираются организация, форма отчёта и её строки. Организацию можно создать или переименовать; доступное архивирование убирает её из активной работы. Перед удалением или архивированием внимательно прочитайте подтверждение.

Для новой позиции укажите её название, категорию и изготовителя/поставщика. Категории включают ПКИ, ДСЕ, составную часть, готовое изделие и сборочный комплект. Категория влияет на группировку и попадание в сводные блоки; выбирайте её по фактическому назначению позиции.

В месячных формах настройте:

- номер позиции и обозначение;
- наименование и норму входимости;
- каждого производителя отдельной строкой;
- договорной объём каждого производителя;
- при необходимости изображение PNG/JPEG до 2 МБ;
- для головной площадки — связи с отчётами дочерних обществ.

Норма входимости — количество данной части на одно готовое изделие. Например, при норме 4 и фактическом выпуске 200 изделий расход равен `200 × 4 = 800` частей. Это настройка нормы позиции; отдельного пользовательского редактора версий BOM, утверждения спецификаций и периодов их действия в этой форме нет.

«Копировать позицию» копирует структуру; это не команда переноса сохранённых числовых данных. Производитель с историей может остаться видимым с пометкой «архив». Закончив настройку, нажмите **«Применить настройки»** и подтвердите изменения кодом администратора.

Источник: [окно настройки](../frontend/src/features/workspace-settings/WorkspaceSettingsDialog.tsx), [детали месячной позиции](../frontend/src/features/workspace-settings/SubsidiaryDetailEditor.tsx), [показатели и формулы](../frontend/src/features/workspace-settings/PositionFieldsEditor.tsx).

## 4. Вкладка «Дочерние общества»

### Что заполнять

1. Выберите нужное общество в поле «Организация».
2. Ответственный заранее заполняет изделие, шифр, изготовителя и месячный план в разделе «План и сведения». В обычном интерфейсе эти сведения доступны для чтения.
3. Выберите месяц и введите «Выпущено, шт.». Значение описывает выпуск изделия отчёта, а не поступления всех его комплектующих. На обычном экране сохраните его верхней кнопкой «Сохранить» с личным кодом ответственного.
4. В основной таблице заполните начальный остаток позиции и поступление за месяц по каждому производителю.
5. В недельных ячейках укажите расход по соответствующему производителю. Недельные значения в текущей форме имеют смысл расхода; не переносите в них поставку из исходной книги без проверки назначения поля.
6. Сохраните основную таблицу. Выберите «Остаток на конец недели» и проверьте результат.

| Поле | Кто и что вводит |
|---|---|
| №, обозначение, наименование, входимость | Задаются в настройках позиции. |
| Производитель и объём по договору | Задаются отдельно для каждого производителя в настройках. |
| Остаток на начало | Один общий остаток позиции на выбранный месяц. |
| Поступило за месяц | Вводится отдельно по каждому производителю. |
| Недели | Вводится расход за соответствующий недельный период. |
| На складе | Общий расчёт позиции на выбранную неделю. |
| Дефицит / профицит | Общий расчёт относительно месячного плана выпуска. |

### Как проверять расчёт

`Остаток на конец недели = начальный остаток + поступления за месяц всех производителей − внесённый расход по выбранную неделю включительно`.

`Дефицит / профицит = начальный остаток + поступления за месяц всех производителей − план выпуска × входимость`.

Пример: начальный остаток 500, поступления 2000 и 1000, план 1000, входимость 4. Отклонение: `500 + 2000 + 1000 − 1000 × 4 = −500`. При внесённом расходе 300 остаток составляет `500 + 2000 + 1000 − 300 = 3200`.

Отрицательное отклонение означает недостаток, положительное — избыток. Расход повторно из отклонения не вычитается. Если не указан начальный остаток или поступления активного производителя, зависимый расчёт остаётся пустым. Расход суммируется по внесённым значениям; пустые исходные ячейки остаются пустыми.

Недели строятся по календарю понедельник–воскресенье. Крайний фрагмент месяца из одного-двух дней присоединяется к соседней неделе; фрагмент от трёх дней остаётся отдельным. Поэтому в месяце может быть четыре или пять отчётных недель.

Годовые показатели шапки суммируют сохранённые месячные значения и показывают количество заполненных месяцев. Это не доказательство полноты годового отчёта: незаполненные месяцы не превращаются в нули.

Источник: [формирование строк и расчёты](../backend/application/subsidiary_report.py), [календарь](../backend/application/report_calendar.py), [месячные поля](../frontend/src/widgets/report-matrix/SubsidiaryControls.tsx).

## 5. Вкладка «Головная площадка»

### Компактная шапка

В одной строке показаны **годовой план**, **название изделия** и **шифр изделия**.
Годовой план рассчитывается из сохранённых месячных планов и не вводится вручную.
На обычном экране эта строка предназначена для чтения. Название, шифр и прочие
сведения меняет ответственное лицо в разделе «План и сведения».

Изготовитель, изображение, расширенные показатели и настройка кодов находятся
в разделе «План и сведения». Сохранённые реквизиты и значения продолжают учитываться
в расчётах и экспорте.

Под шапкой выберите месяц: план доступен для чтения, фактический выпуск — для заполнения. Если выпуск задаётся по кодам, раскройте «Выпуск по кодам» и внесите факт по каждому
коду выбранного месяца. Общий итог рассчитывается автоматически. Пустые значения
не превращаются в нули; сохранение выполняется верхней кнопкой «Сохранить».
Если сумма впервые заменяет прежний общий выпуск и отличается от него, проверьте
значения и явно подтвердите замену суммы. Названия кодов и их планы меняет ответственное лицо в «План и сведения».

### Составные части

Администратор настраивает входимость, производителей, договорные объёмы и месячный **план каждого производителя**. На обычном экране заполните общий начальный остаток части и месячный **факт каждого производителя**. Плановые и расчётные поля здесь не редактируются.

| Расчёт | Формула |
|---|---|
| Использовано | Фактический выпуск готовых изделий × входимость части. |
| На складе | Начальный остаток + сумма факта производителей − использовано. |
| Дефицит / профицит | Начальный остаток + сумма факта производителей − сумма плана производителей. |

План производителей уже выражен в штуках составной части: повторно умножать его на входимость не нужно.

Пример: начальный остаток 100, производители дали 500 и 500 частей; готовых изделий выпущено 200, входимость 4, план частей 1000. Расход: `200 × 4 = 800`; склад: `100 + 500 + 500 − 800 = 300`; отклонение: `100 + 1000 − 1000 = +100`.

### Проверка по дочерним обществам

В настройке части выберите «Связать отчёт» и соответствующее дочернее общество. К одной части можно привязать несколько обществ. Один дочерний отчёт нельзя назначить одновременно разным частям.

Программа сравнивает общий факт части у головной площадки с суммарным выпуском связанных обществ за тот же месяц. Отсутствующий выпуск общества или превышение его суммы вызывает пояснение с обществом, месяцем и величинами. Исправьте исходный факт или связь; отчёт с таким расхождением нельзя подтвердить.

Связь проверяет согласованность, но не заполняет факт головной площадки вместо пользователя. Старые значения прежней формы доступны в раскрываемом блоке «Данные прежней формы» и не прибавляются повторно к новому расходу.

Источник: [расчёты головной площадки](../backend/application/head_site_report.py), [правила шапки и кодов](../backend/application/report_header.py), [редактор шапки](../frontend/src/widgets/report-matrix/ProductionHeader.tsx), [ADR-0015](decisions/ADR-0015-head-monthly-report.md).

## 6. Вкладка «Ежедневный отчёт»

### Движение по датам

Для каждой позиции значения вводятся по календарным дням. Администратор заранее выбирает набор строк и категорию, указывает поставщика/изготовителя и название позиции. Плановые строки остаются видимыми, но на обычном экране доступны только для чтения.

| Набор | Что заполнять |
|---|---|
| ПКИ, ДСЕ, составная часть | «Получено», «Использовано» по дням. «Остаток» рассчитывается. |
| Сборочный комплект | Выпуск, отправку и прибытие по датам; план выпуска заполняет ответственное лицо в «План и сведения». |
| Готовое изделие | Выпуск, отправку и прибытие по датам; план выпуска заполняет ответственное лицо в «План и сведения». |

В разделе администратора, чтобы добавить часть дочернего общества, используйте **«Расход составной части»**. Для расчёта остатка откройте «Изображение, показатели и формулы», задайте **начальный остаток и его дату**. До этой даты остаток по данной настройке не рассчитывается. Затем вносите поступления и расход по дням; штатная формула учитывает внесённые движения накопительно.

Обязательные строки исходной формы нельзя удалить обычной кнопкой удаления показателя. Названия доступных строк можно уточнять. В блоках выпуска комплекта или изделия поле «Коды / модификации через запятую» и кнопка «Добавить строки по кодам» добавляют отдельные строки плана, выпуска и прибытия для заданных кодов, сохраняя общие строки и прежние данные. Эти дополнительные строки сами по себе не связывают ежедневные значения с месячной таблицей кодов головной площадки.

### Итоги и комплектность

В выпадающем списке выберите месяц. Основная таблица показывает только его дни и один столбец **«Накопительный итог»** — с 1 января по конец выбранного месяца включительно. Отдельных столбцов прошедших месяцев нет. Приход, расход и выпуск складываются из сохранённых значений; расчётный остаток берётся на конец периода, остатки разных дней не суммируются. Пустой показатель не заменяется нулём.

Нижняя таблица **«Составные части дочерних обществ — месячная сводка»** содержит настроенные позиции категории «Составная часть» со строками «Получено», «Использовано», «Остаток». Для каждой выводятся месячные показатели «Всего получено», «Всего использовано», «Остаток изделий». ПКИ не включаются в эту сводку как составные части. Источник — сохранённые ежедневные данные этой формы, а не автоматическая загрузка из вкладки «Дочерние общества».

Для комплектности выберите подходящий готовый расчёт в настройках позиции и задайте норму. Например, при остатке 71 и норме 3 доступно `floor(71 / 3) = 23` комплекта. Итог готовых комплектов — минимальная обеспеченность среди позиций, где включён показатель комплектности. Проверяйте, что настроены все обязательные части: пропущенная позиция не станет ограничителем автоматически.

Подписи блока **«Склад и комплектность»** редактируются через «Настроить рабочее поле». Переименование не создаёт связи с производственными кодами. Строка «На складе по кодам/модификациям» остаётся заблокированной, пока её бизнес-привязка не реализована; не считайте пустое поле готовым расчётом склада по кодам.

Месячный расход головной площадки не раскладывается автоматически по дням. Не переносите его целиком в несколько дней и не суммируйте повторно один выпуск из двух форм.

## 7. Excel: импорт, исходные книги и экспорт

### Книга рабочей формы

Импорт, сопоставление и изменение сохранённой исходной книги требуют кода администратора: исходная книга может менять структуру и сопоставления. Экспорт доступен из меню «Ещё». Предпросмотр импорта сохраняет служебный пакет проверки, поэтому его открытие также требует кода администратора.

1. Сохраните изменения и выберите нужные форму и организацию.
2. Для заполнения через Excel сначала выполните «Экспорт Excel»: получите книгу с координатами соответствующей рабочей формы.
3. После заполнения нажмите «Импорт Excel» и выберите файл.
4. Проверьте строки предпросмотра: новые, изменённые, совпадающие и ошибочные значения.
5. Исправьте ошибки или сопоставления; затем нажмите «Подтвердить импорт». До подтверждения рабочие данные не изменяются.

Повтор уже проведённого импорта не должен создавать дубли. Перед проведением импорта создаётся резервная копия. Не меняйте служебную структуру книги, выгруженной для другой формы или организации, чтобы обойти проверку.

### «Сохранённые отчёты Excel»

Распознанные исходные книги могут сохраняться отдельным отчётом. Откройте его через список **«Сохранённые отчёты Excel»**, выберите лист, измените разрешённые ячейки двойным щелчком и нажмите «Сохранить изменения». «Экспорт Excel» выгружает эту книгу; «К рабочей форме» возвращает в основную матрицу.

Это отдельный режим. Сохранение исходной книги не означает автоматического переноса всех её значений в рабочую форму. Для переноса используйте этап сопоставления: выберите позицию, показатель и период, подтвердите правильность каждого значения. Для исключаемых полей укажите причину. После проверки сопоставления подтвердите импорт.

Назначение недельных полей, формулы и подписи старой книги могут отличаться от действующей рабочей формы. Нельзя автоматически считать «поставку» старого образца текущим «расходом». Отображение исходной сетки и поддерживаемый пересчёт формул не заменяют полноценный Excel со всеми его возможностями.

Источник: [импорт и транзакции](../backend/application/excel_reports.py), [режим исходной книги](../frontend/src/features/reference-reports/ReferenceReport.tsx), [ручное сопоставление](../frontend/src/features/reference-reports/ReferenceTransfer.tsx).

## 8. Подтверждение отчёта пользователем и PDF

1. Выберите месяц; для дочернего общества проверьте также неделю остатка.
2. Внесите правки и нажмите **«Сохранить»**. В открывшемся окне выберите ответственное лицо и введите его личный код. Подтверждение означает, что вы проверили данные. Руководитель проекта, проверяющий и администратор могут использовать собственные коды.
3. Программа сохраняет данные и создаёт криптографическую подпись актуального отчёта. При неверном коде или отмене черновик остаётся без записи.
4. Если появилось **«Сохранено, но не подтверждено»**, данные уже записаны. Прочитайте причину, исправьте расчётное расхождение и сохраните ещё раз. Не считайте такую отметку действующей подписью.
5. Для печати нажмите **«Печать / PDF A4»** рядом с «Сохранить». Программа автоматически запросит личный код, подтвердит сохранённый отчёт и предложит место для PDF. Несохранённые изменения сначала сохраните. Откройте PDF и распечатайте его средствами просмотра.

Отдельной кнопки «Подтвердить данные» больше нет. Если нужного человека нет в списке, администратор добавляет его через «Ответственные лица».

Подпись относится к снимку выбранного отчёта: учитываются его период, организация, шапка и значения, включённые в печатное представление. Для ежедневного отчёта в месячный снимок также входят данные предыдущих месяцев. Изменение данных или параметров может потребовать повторного подтверждения.

| Сообщение | Действие |
|---|---|
| Данные не подтверждены | Проверить и подписать. |
| Подтверждено | Подпись корректна для текущего снимка. |
| Данные изменились | Проверить изменения и подписать заново. |
| Подпись недействительна | Не полагаться на отметку; проверить целостность базы и резервную копию. |
| Прежняя отметка без криптографической подписи | Подписать текущую версию персональным ключом. |

В PDF подтверждение занимает **две строки**: ФИО, время UTC и алгоритм; отпечаток ключа и подпись. Закрытый ключ не печатается. Если отчёт не подтверждён или подпись устарела, PDF показывает соответствующее состояние вместо действующей отметки.

Ключи Ed25519 хранятся в зашифрованной базе; каждый закрытый ключ дополнительно защищён личным кодом. Смена администратора и сброс забытого кода в этой версии не предусмотрены. Для переноса доступа нужны **база вместе с её файлом `.keys.json`**, см. раздел 9.

Это внутренняя криптографическая подпись данных, а не КЭП и не подпись всего PDF сертификатом: обычный просмотрщик PDF не будет показывать её как PAdES-сертификат. Проверку выполняет программа по данным базы. ФИО задаётся пользователем; паспортная личность не проверяется. Полная замена базы вместе с ключами не обнаруживается без независимой доверенной копии.

Источник: [инструкция по ключам dev.22](test-cases/alpha-dev22.md), [состав печатных строк](../backend/application/report_signature_caption.py), [ADR-0016](decisions/ADR-0016-report-signatures.md).

## 9. Резервная копия, обновление и восстановление

По умолчанию рабочая база — `data/reporting.sqlite3`, а файл доступа — **`data/reporting.sqlite3.keys.json`**. Они образуют пару. Переносите и сохраняйте их вместе при закрытой программе. В `.keys.json` находятся имена, роли и защищённые личными кодами ключи доступа; сами коды в открытом виде не хранятся. Не редактируйте этот файл вручную.

Файл `data/reporting.sqlite3.device.json` содержит настройку автоматического открытия для Windows. Он не заменяет пару БД и `.keys.json` и не гарантирует открытия на другом компьютере. При его отсутствии программа запросит код один раз. Если сохранить настройку не удалось, программа покажет сообщение; отчёты останутся открыты, но следующий запуск может снова потребовать код.

Резервные копии находятся в `backups/`. Новые копии защищённой базы также зашифрованы и сопровождаются соответствующим файлом `.keys.json`. Копия перед импортом или изменением структуры не заменяет регулярное резервирование всей рабочей папки. Старые копии, сделанные предыдущей незашифрованной версией, автоматически не шифруются и не удаляются.

### Обновление прежней базы

1. Сохраните изменения, закройте программу и скопируйте всю старую папку в безопасное место.
2. Распакуйте новую сборку в отдельную папку. Перенесите `data` и необходимые `attachments`, `imports`, `exports`, `backups`. При наличии перенесите `config/app.local.toml`, не заменяя новые стандартные настройки.
3. Если путь базы переопределён в настройках, переносите фактическую базу и её файл доступа по этому пути.
4. Для уже зашифрованной базы в окне **«Настроить открытие без кода»** один раз введите действующий код проверяющего с разрешённым входом или администратора. Для прежней незашифрованной базы введите код прежнего администратора и нажмите **«Включить защиту и открыть»**; если профилей ещё не было, создайте администратора. Отчёты и подписи сохраняются. После успешной настройки последующие запуски на этой учётной записи Windows не требуют входа.
5. Прежние пользователи с ролью подписанта становятся проверяющими. В разделе **«Администратор» → «Ответственные лица»** нажмите **«Разрешить вход»** для каждого прежнего пользователя, введите его действующий личный код и подтвердите действие кодом администратора. После этого его код сможет открыть базу после переноса или восстановления настройки Windows. Новые проверяющие получают эту возможность при создании. Руководителю проекта такой код восстановления не выдаётся; обычный запуск на настроенном компьютере доступен без него.
6. Проверьте организации, несколько контрольных чисел и прежние подтверждения. Сохраните свежую полную резервную копию.

### Восстановление доступа

Если свой код забыл один пользователь, другой проверяющий или администратор с разрешённым входом может открыть базу своим кодом. Это не восстанавливает забытый код и не передаёт права администратора. Забытый код администратора лишает возможности изменять настройки и выдавать новые ключи.

На настроенной учётной записи Windows чтение может оставаться доступным через файл `.device.json`, даже если личный код забыт. Это не позволяет подписывать, сохранять или администрировать без кода. Если автоматическое открытие недоступно, для переноса и восстановления нужны согласованные БД и `.keys.json` и действующий код проверяющего или администратора. Универсального кода восстановления нет.

Для восстановления данных закройте программу и сохраните отдельную копию текущей папки. Восстанавливайте базу и соответствующий ей файл доступа из одной согласованной копии в отдельную папку приложения; привлеките ответственного специалиста. Не запускайте старый EXE на базе с новыми миграциями. Встроенной кнопки полного восстановления в рабочей форме нет.

### Что защищает шифрование

SQLCipher шифрует файл базы и её новые резервные копии. Программа проверяет права при каждом запросе записи; сохранение отчёта требует свежего личного кода. Создание пользователя использует действующий сеанс администратора. Закрытые ключи защищаются Argon2id и ChaCha20-Poly1305. Шифрование не защищает от удаления или подмены файлов пользователем с правами файловой системы, доступа к памяти работающей программы и вредоносного ПО на компьютере. Личный код доступа к ключу базы выдаётся только проверяющим и администратору. Для автоматического открытия дополнительная обёртка ключа хранится в `.device.json` и защищается Windows DPAPI текущей учётной записи. Поэтому любой человек или процесс, работающий под этой же учётной записью Windows и имеющий доступ к папке, может читать отчёты без личного кода программы. Автоматическое открытие не устанавливает личность и не создаёт административный сеанс. Структура форм, организации и ключи дополнительно защищены правами администратора; план и сведения доступны ответственным. Проверяющий, имеющий доступ к ключу расшифровки, технически может использовать внешние инструменты; программа не заменяет защиту учётной записи Windows и контроль доверенных ответственных лиц. Экспортированные Excel/PDF и старые исходные книги не превращаются в зашифрованные файлы автоматически.

## 11. Короткие ответы на частые вопросы

**Почему кнопка сохранения недоступна?** Завершите редактирование текущей ячейки клавишей Enter. Проверьте сообщения рядом с формой. Если изменений нет, сохранять нечего. Для плана и сведений откройте одноимённый раздел.

**Почему остаток пустой?** Наведите указатель на результат: подсказка укажет источник и место заполнения. Проверьте начальный остаток, его дату в ежедневной форме, поступления всех активных производителей и сообщения об ошибках. Пустые исходные значения не означают нули.

**Почему процент выполнения отсутствует?** Проверьте план и факт. При нулевом плане процент не рассчитывается.

**Почему не получается подтвердить отчёт?** Сохраните все изменения, проверьте месяц/неделю, личный код ответственного. Исправьте сообщения о формулах и расхождениях с дочерними обществами.

**Почему прежняя подпись стала устаревшей?** Текущий снимок отличается от подписанного. Перепроверьте данные и подтвердите новую версию.

**Можно ли перенести только PDF на другой компьютер и проверить подпись программой без базы?** В текущем интерфейсе отдельной проверки PDF без базы нет. Печатная подпись — часть внутреннего подтверждения снимка.

**Как начать проверку после установки?** Сначала на копии базы заполните одну позицию за один месяц, проверьте формулы вручную, сохраните, перезапустите программу, затем сформируйте Excel/PDF и выполните подпись. После этого переходите к полному рабочему периоду.

Экспорт Excel отклоняет числа, которые нельзя сохранить без потери точности в числовом формате Excel (15 значащих цифр). Программа показывает объяснение; исходные данные и существующий файл не изменяются. Для таких величин используйте просмотр в программе или PDF.
