# Запуск с общей папки

## Размещение

Распакуйте ZIP в отдельную общую папку Windows/SMB. Пользователи запускают
`ReportingSystemNetwork.exe`. Для совместной работы все используют одну
папку `shared` рядом с EXE; права чтения/записи выдаются средствами Windows.
Администратор должен заранее создать папку данных. Установка программы,
службы, Python, Node.js или отдельного браузера на клиенте не требуется.

При первом запуске отображается подготовка. Неизменяемый комплект проверяется
по SHA-256 и копируется на локальный диск. Последующие запуски проверяют ту же
копию. Общая SQLite не открывается с сетевого диска: клиент принимает проверенную
зашифрованную пару базы и ключевых конвертов в локальное состояние.
Личный код вводится на каждом компьютере для первого доступа; автоматическое
чтение на этом компьютере не подтверждает защищённые действия от имени пользователя.

`ReportingSystem.exe` запускает прежний локальный режим. Локальная база рядом с
ним не становится общей автоматически. Для изменения способа хранения данных
используйте предусмотренный перенос, сохраняя исходную папку.

Перед переносом закройте исходную локальную программу на всех компьютерах.
В пустом общем хранилище выберите «Перенести существующие локальные отчёты»,
введите код действующего администратора и укажите локальную защищённую базу.
Файл ключей рядом с базой также необходим. Исходные файлы сохраняются;
после успешного переноса пользователи работают через сетевой запуск.

## Настройки

По умолчанию: общая папка `shared`, подготовка до 300 секунд, ожидание писателя
до 15 секунд. При другом расположении создайте `network.local.json` рядом с
`ReportingSystemNetwork.exe`:

```json
{
  "protocol_version": 1,
  "shared_directory": "\\\\SERVER\\Reports\\SharedData",
  "startup_timeout_seconds": 300,
  "writer_lock_timeout_seconds": 15
}
```

SERVER — пример: укажите фактический сервер и ресурс. Порт/API не требуются.
Относительный путь считается от сетевого EXE. У всех клиентов должен быть один
источник данных. Таймаут подготовки: 30–900 секунд; блокировки: 1–120 секунд.
Конфигурация маршрута не входит в проверяемый исполняемый кэш.

## Работа и восстановление

Статус сети сообщает, актуальна ли общая версия. Кнопка обновления получает
новые данные явно. При несохранённом вводе или неизвестном результате обновление
блокируется. Конфликт не удаляет черновик и не объединяет значения автоматически.
«Сохранено» означает подтверждённую публикацию общего CURRENT.

При недоступности сервера запись запрещена. При неизвестном исходе сначала
проверьте результат той же операции; не создавайте новый пакет наугад. Если
повреждён CURRENT существующего набора, клиент не создаёт вместо него новую базу.
Сохраните shared и локальные состояния, закройте клиентов и восстановите
проверенную пару в новую папку. Подтверждённые поколения автоматически не удаляются.

Открытые XLSX, PDF, профиль браузера, настройки интерфейса и DPAPI-копия остаются
локальными. Сохранённые источники канонического импорта находятся внутри
зашифрованной базы, поэтому повторная проверка доступна другому клиенту.
Старый пакет, исходник которого отсутствует, потребует повторного выбора книги.

## Границы проверки

Файловая схема доверяет правам SMB: приложение не защищает файлы от ручного
изменения пользователем с правом записи. Отзыв роли блокирует дальнейшие команды,
но не делает ранее скачанные данные недоступными. Технические следы Windows,
Defender и WebView2 независимы от отключённых собственных логов программы.

Перед рабочим выпуском нужны проверки на целевых Windows 10/11, сервере,
физических клиентских ПК и реальной сети: сохранение/подтверждение, импорт,
печать, обрыв связи, конфликт писателей и восстановление. CI loopback SMB и
локальные fault-injection проверки отмечаются отдельно в протоколе сборки.
