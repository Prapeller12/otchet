# Система производственной отчётности

Репозиторий программы автоматизации и централизации производственной отчётности.

## Текущее состояние

В репозитории реализован сквозной технический preview: React/Vite-матрица, PyWebView bridge,
application-service и SQLite-хранилище неизменяемых ревизий ячеек. Три рабочие формы
открываются в общем матричном интерфейсе; ввод сохраняется в локальную БД с различием
пустого значения и подтверждённого нуля. Отдельное окно настройки позволяет менять
изготовителей и позиции, добавлять или архивировать строки, а также вести несколько дочерних
обществ. Суммы ежедневного отчёта выводятся в столбце «Показатель», состояние SQLite и
активной ячейки — в нижней строке. Также подготовлены fail-closed launcher и сценарии
сборки/проверки Windows `onedir`-поставки.

DEV-документация v0.5 утверждена владельцем программы 31.08.2026 и является главным
источником требований текущего этапа.

Полученные формы зафиксированы как `WORKING_REFERENCE`, но не считаются утверждёнными
эталонами. Интерфейс использует только синтетические preview-идентификаторы, не проводит
введённые значения как складские операции и блокирует Excel import/export до утверждения
карты ячеек. Это запускаемый технический preview, но ещё не производственная версия.

Актуальное состояние и блокирующие вопросы перечислены в [docs/project-status.md](docs/project-status.md).

## Обязательные правила

Перед любой работой полностью прочитайте [AGENTS.md](AGENTS.md). Основные неизменяемые ограничения:

- матричная структура исходных Excel-форм сохраняется;
- даты располагаются горизонтально, показатели и объекты — вертикально;
- пустое значение отличается от подтверждённого числового нуля;
- расчёты выполняются backend/domain;
- локальная поставка — переносимый ZIP без установки и прав администратора;
- технические файловые логи и телеметрия по умолчанию выключены;
- пользовательские данные, рабочая БД, импорты, экспорты и резервные копии не попадают в Git.

## Структура

- `backend/` — API, application, domain, инфраструктура, репозитории, миграции и тесты;
- `frontend/` — React/TypeScript интерфейс с каноническими матричными формами;
- `config/` — внешняя конфигурация, роли и подтверждённые правила расчётов;
- `resources/` — утверждённые шаблоны, схемы, справочники и графические ресурсы;
- `docs/` — архитектура, контракты, спецификации и решения ADR;
- `scripts/` — проверка репозитория и будущие сценарии сборки/упаковки.

## Запуск технического preview

Готовая Windows x64 тестовая сборка публикуется в
[GitHub Releases](https://github.com/Prapeller12/otchet/releases/tag/test-v0.1.0-dev.2).
Скачайте ZIP, полностью распакуйте его и запустите `start.cmd`. Python и Node.js на
пользовательском компьютере не требуются.

Для браузерной разработки (данные хранятся только в памяти вкладки):

```bash
npm ci --ignore-scripts --no-audit --no-fund
npm run dev
```

Для реального сохранения требуется PyWebView-запуск с локальной SQLite. Пользовательский
Windows ZIP собирается скриптом `scripts/build_windows.ps1` только на Windows и только при
наличии распакованного WebView2 Fixed Runtime; неполная поставка отвергается проверкой.

## Начало работы разработчика

Требования dev-контура: Git, Python 3.12 и Node.js для проверки frontend-контракта. Эти
зависимости относятся только к разработке; конечному пользователю устанавливать их не
потребуется.

```bash
python3 -m venv .venv
.venv/bin/python -m pip install "jsonschema>=4.23,<5" "pytest>=8.3,<9" "ruff>=0.6,<1" "mypy>=1.11,<2"
.venv/bin/python scripts/verify_repository.py
.venv/bin/ruff check backend scripts
.venv/bin/ruff format --check backend scripts
.venv/bin/mypy backend scripts
.venv/bin/python -m pytest
npm ci --ignore-scripts --no-audit --no-fund
npm run typecheck
node frontend/tests/contracts/report-cell-contract.test.mjs
npm run test:frontend
npm run build
```

Работайте в отдельной ветке и перед объединением изменений заполните шаблон pull request. Неподтверждённые бизнес-правила фиксируйте как `OPEN`, не подменяя их реализацией.
