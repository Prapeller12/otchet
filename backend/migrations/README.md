# Миграции

Миграции добавляются последовательно. Применённая миграция никогда не редактируется; исправление оформляется новой миграцией.

`0001_initial_schema.sql` создаёт подтверждённое ядро SQLite: организации, изделия,
компоненты, версии и строки BOM, складские и производственные операции. Количества хранятся
как проверенные десятичные строки, внешние ключи включены, пересекающиеся утверждённые версии
BOM запрещены, проведённые операции неизменяемы и исправляются отдельным сторно.

`0002_freeze_approved_bom.sql` блокирует изменение и удаление состава утверждённой или
выведенной из действия версии BOM. После утверждения разрешён только переход
`APPROVED` → `RETIRED`; для изменения норматива создаётся новая версия.

`0003_report_fact_application.sql` добавляет минимальный вертикальный срез деклараций
отчётных фактов, идемпотентности команд и бизнес-аудита. Координаты не содержат Excel-
адресов. Их соответствие конкретным строкам утверждённых форм пока имеет статус
`WORKING_REFERENCE`; роли, планы и правила закрытия периода миграция намеренно не вводит.

`0004_report_workspace_configuration.sql` добавляет профили головной площадки и дочерних
обществ, а также пользовательские группы строк для каждой формы. Удаление групп запрещено:
они переводятся в неактивное состояние, чтобы сохранённые факты не теряли координаты.

Применение:

```bash
python -m backend.infrastructure.database.migrator data/reporting.sqlite3
```

Мигратор применяет файлы по порядку, записывает SHA-256 и отклоняет изменение уже применённой
миграции, неизвестную версию или историю, которая не является непрерывным префиксом доступных
миграций. Полные таблицы пользователей, ролей, периодов, планов, договоров, импорта и аудита
будут добавлены отдельными миграциями только после фиксации соответствующих контрактов.
