# Backend

Python-backend разделён по слоям:

- `api/` — HTTP/IPC-адаптеры без бизнес-формул;
- `application/` — сценарии использования и транзакционные границы;
- `domain/` — доменные сущности, точные значения и расчёты;
- `repositories/` — абстракции доступа к данным;
- `infrastructure/` — реализации SQLite/PostgreSQL и внешние адаптеры;
- `migrations/` — последовательные неизменяемые миграции;
- `tests/` — unit, интеграционные и контрактные тесты.

Реализованы чистые расчёты в `domain/`, SQLite-мигратор, подтверждённое ядро операций и
неизменяемого BOM, а также первый application-срез деклараций матричных фактов:

- `ReportCellService` атомарно сохраняет batch изменений;
- каждое изменение создаёт неизменяемую ревизию с optimistic revision check;
- `DATA_NOT_PROVIDED` и точное значение `0` сохраняются раздельно;
- нулевая декларация не создаёт нулевую складскую операцию;
- повтор команды защищён idempotency key;
- бизнес-изменение фиксируется в `audit_events`;
- `DesktopBridge` предоставляет JSON-friendly `health`, `bootstrap`, `get_cells` и
  `save_cells` без запуска localhost-сервера.

Соответствие координат конкретным строкам Excel, роли, планы и закрытие периода не
угадываются и имеют статус `WORKING_REFERENCE`. Этот срез является техническим фундаментом
для portable UI, а не утверждённой картой трёх отчётных форм.

Для результата процента с бесконечной десятичной записью требуется отдельное правило
округления; до его утверждения домен возвращает явную ошибку вместо неявной потери точности.
